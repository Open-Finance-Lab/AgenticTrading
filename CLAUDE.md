# CLAUDE.md

Agent guide for Agentic Trading Lab (ATL): rules, commands and traps. Detail lives in `docs/architecture/configuration.md` (per env var; `→ configuration.md` below) and `docs/architecture/backend-internals.md` (subsystems; `→ backend-internals.md § …`). Local setup: `docs/local-run.md`. `docs/superpowers/`: dated specs and plans (history; the tree wins). Short paths (`api/`, `domain/`, `tests/`, `app.py`, …) are under `dashboard/backend/`.

## What this repo is

**Agentic Trading Lab**: open-source platform for LLM-powered trading agents (backtests, decision-log inspection, leaderboards). Robinhood real money is off (`ROBINHOOD_LIVE_ENABLED = False`, `dashboard/backend/domain/backtesting/constants.py`) and there is no paper-trading feature (`PAPER_TRADING_ENABLED`, same file and `dashboard/frontend/app.js`; `/paper/*` is one shared Alpaca paper account); both are constants, not env vars.
- `dashboard/`: the shipping product (FastAPI backend, static frontend, backtest CLIs in `dashboard/scripts/`). Almost all work happens here.
- `packaging/agentictrading/`: Python SDK, installed from source (PyPI `0.1.0` is stale).
- `orchestration/`: imported NeurIPS 2025 FinAgent research code (hard-coded conda paths), imported by nothing in `dashboard/` or the `Dockerfile`; root `pyproject.toml`/`uv.lock` are its alone. Separate project unless asked.

## Critical: the backend is the `dashboard.backend` package

**Package contract.** `dashboard/backend/` is the `dashboard.backend` Python package. Import by full path (`from dashboard.backend.database import db`); the repo root must be on `sys.path`. Run from the repo root by import string (`uvicorn dashboard.backend.app:app` or `python -m dashboard.backend.app`), never `python dashboard/backend/app.py` (the `dashboard.backend.*` imports fail). Scripts in `dashboard/scripts/` get the root via `_bootstrap.ensure_repo_root()`, the only sanctioned `sys.path` mutation. `domain/` and `infrastructure/` must not import `api/` or `app.py`. Pinned by `tests/test_architecture_boundaries.py`. Layout: `docs/architecture/dashboard-target-structure.md` §0 (later sections are historical).

## Common commands

Run from the repo root.
```bash
pip install -r requirements.txt            # uv-compiled from requirements.in; Python 3.13
pip install -r requirements-test.txt       # pytest + pytest-timeout, not in requirements.txt
uvicorn dashboard.backend.app:app --reload # http://localhost:8000
dashboard/scripts/run_local_safe.sh [port] # needs .venv/ (docs/local-run.md §2); no spend, prod DB or mail; seed-DB copy
pytest dashboard/backend/tests/ -v
pytest dashboard/backend/tests/ --timeout=180 -p no:cacheprovider   # the CI form
pytest dashboard/backend/tests/test_protocol_api.py::<test_name> -x # single test
(cd packaging/agentictrading && pytest tests/)                      # SDK suite
python dashboard/scripts/backtest_hourly_agent.py --no-llm --start 2026-03-01 --end 2026-04-23
(cd dashboard/landing && npm ci && npm run typecheck && npm run build)   # landing, as CI runs it
```
No linter or formatter is configured.
- **Trap:** a plain `uvicorn` run and the backtest CLIs (`--clear` wipes it) use the committed seed DB `dashboard/storage/data/backtest.db` (the `DATABASE_PATH` default); the server also loads the keys in `dashboard/.env` (the CLIs read only the shell env and `credentials/alpaca.json`). Use `run_local_safe.sh`, or point `DATABASE_PATH` at a copy.
- **Test isolation:** `dashboard/backend/tests/conftest.py` pins `DATABASE_PATH` to a temp file before any backend import and strips the three `*_DATABASE_URL` and cookie env, and sets `ATL_CSRF=0`: CSRF is off suite-wide, so a browser write that skips `API.request`/`csrfHeaders()` (`app.js`) passes tests and 403s (`csrf_failed`) in prod. `@pg_only` tests need `TEST_POSTGRES_URL` (a local Postgres 18; CI has one) and skip without it. CI runs the full suite and it gates the prod deploy: red on a fresh checkout is a real regression.
- **Test layout:** mostly flat `tests/test_*.py`; newer ones in subdirs mirroring `domain/`/`infrastructure/` (also `conformance/`, `integrations/`); shared helpers are `tests/_*.py`; an autouse fixture stubs the daily-refresh thread (opt out: `@pytest.mark.daily_refresh_background`).

## Environment & credentials

`app.py` loads only `dashboard/.env`, not the repo root (whatever its comment says); every `load_dotenv` caller in `dashboard/scripts/` (`deploy_leaderboard_model.py` bills) and the Discord bot also read the root `.env`. Template: the root `.env.example`. Alpaca keys fall back to `credentials/alpaca.json`; `.env` and `credentials/*` are gitignored. Full per-variable reference: `docs/architecture/configuration.md`.

**Parse operator-set values defensively:** junk, blank or out-of-range logs and falls back to the default, never raises. A bare `int()` at module scope in `api/routers/backtests.py` once killed app boot. Older knobs still parse bare at import (e.g. `MAX_LEGACY_ACTIVE_*`, `MAX_ACTIVE_RUNS_*`, `V2_RATE_LIMIT_*`; full list: **Trap** in `configuration.md`), so a blank Render field there still kills boot.

**Adding an env var:** document it in `.env.example` and `configuration.md`, and index it here if a rule binds. If it is read at import or touches spend, mail, auth or caching, `os.environ.pop` it in `dashboard/backend/tests/conftest.py` and `monkeypatch` it per test, or a developer's shell silently changes what the suite asserts (or spends money). Spending flags are strict opt-in; blank a new spending key or flag in `run_local_safe.sh` too.

**Market data**
- `ALPACA_DATA_FEED` (default `sip`; `iex|sip|delayed_sip|otc`; a bad value is fatal): the tape behind every curve. Curves on different tapes are not comparable, so force-refresh the boards after a change (Competition: `GET /api/v1/leaderboard?refresh=true`; Live: `POST …/live/refresh?force=true`; both redo baselines only. Not `/daily/refresh`: its default bills every LLM). → `configuration.md`
- `ALPACA_SIP_DELAY_MINUTES` (15) / `ALPACA_ALLOW_RECENT_SIP` (off): Basic-plan SIP `end` clamps to now-15m; a delay over ~65 min drops the closing bar (`alpaca_bars.clamp_end_for_sip`).
- `ATL_BAR_CACHE` (default ON; anything but `1/true/yes/on` turns it off, junk with a WARNING) + `ATL_BAR_CACHE_DIR`, `_MAX_MB`, `_TTL_DAYS`: on-disk parquet bar cache inside `fetch_bars`; the suite forces it off. → `configuration.md`
- `ATL_BAR_CACHE_WARM` (**strict opt-in; spends money**): when truthy, boot warms the default backtest windows with Alpaca calls. Default-on would bill every image, fork and `--reload`; set it only in Render (the suite forces `0`). → `configuration.md`
- `IFIND_REFRESH_TOKEN` / `IFIND_ACCESS_TOKEN` (+ optional `IFIND_BASE_URL`): iFinD A-share credentials, set in Render (the refresh token wins); the source also needs `ENABLE_IFIND_ASHARE=true`. → `configuration.md`
- `IFIND_ALLOW_CORPORATE_ACTION_GAPS` (strict opt-in): A-share prices are **unadjusted**; off, a >21% overnight gap (usually 除权除息) raises `CorporateActionGapError`; armed, the run proceeds and lists the dates in a results-panel row: **a labelled wrong number, never a silent one** (`engine.py` cites this). → `configuration.md`
- `NEWS_FEED_FROZEN` (unset = frozen; the FinSearch feed is paused): serves `dashboard/config/news_demo_snapshot.json` as "Demo news". To resume, restart the droplet timers, then set `0`. → `configuration.md`

**LLM execution**
- `LLM_PROVIDER_READ_TIMEOUT_SECONDS` (default 180): deadline of ONE provider attempt (the whole generation). ⚠ Every SDK client gets `max_retries=0` and `timeout=provider_http_timeout()` from `infrastructure/llm/http_policy.py`; retries belong to `LLMExecutionService` (billed runs) or `http_policy.call_with_retries` (everything else). An SDK replay of a read timeout is a silent, billed generation (`test_chat_algo_client_policy.py`). → `configuration.md`
- `LLM_ESCALATE_CEILING_ON_RETRY` (opt-in): an empty backtest reply retries once at the recovery ceiling instead of 4x at the same one (`escalate_ceiling_on_retry()` docstring).
- `PIPELINE_SECONDS_PER_LLM_CALL` (default 15): assumed seconds per call behind the pipeline+llm window 422; a calibrated estimate, not a worst-case ceiling. → `configuration.md`
- `ATL_PLATFORM_PROVIDER_ORDER` (default `commonstack,openrouter`): ATL Credits provider order; omit a lane to pull it (no code change). → `configuration.md`
- `MAX_AI_HEDGE_FUND_TRADING_DAYS` (default 10; 0 disables the hosted runtime): AI Hedge Fund window bound, capped by the step timeout. → `configuration.md`

**LLM billing**
- **LLM backtest billing — the live path (no env var of its own).** `POST /backtest/run` with `decision_source='llm'` on the pipeline runtime is sign-in-only (401) and needs `billing_mode` = `byok` | `platform_credits` (422). The worker gets a signed, secret-free handoff on **stdin**; never put a raw key in argv or env. `infrastructure/llm/execution/service.py` bills **per call by usage** (reserve, settle, release). `attempt_index` spans repeats and failover: select a lane by `provider_id`, never `attempt_index = 1`. Settlement fails closed (`BILLING_FAILED`); BYOK never touches the ledger.
- ⚠ **Only two paths spend Credits:** that layer and research runs (`api/routers/research.py`). Every other LLM call bills operator keys unreserved: leaderboard entries (CommonStack), Discord `/ask`, Trading Algo chat and backtest (`/api/algo/*`), the AI Hedge Fund bridge (`OPENROUTER_API_KEY`). `make_llm_client()` without an integration prefers `COMMONSTACK_API_KEY`, so the Trading Algo backtest hits CommonStack though `execute_algo` checks only `ANTHROPIC_API_KEY`.
- ⚠ **Pinned is not deterministic.** Temperature 0 is a request, not an outcome: providers are not deterministic and each bar's prompt embeds the previous bar's answer, so one different draw carries to the end of the run. UI copy never says "deterministic" (`formatBacktestSampling`; `test_backtest_sampling_row.py`). Measure the spread with `python dashboard/scripts/diff_backtest_runs.py <run_a> <run_b>` (exit 2 on a config mismatch unless `--allow-mismatch`).
- Ledger tables, launch preflight (402/403), mid-run `INSUFFICIENT_CREDITS`, the welcome grant, the parent-side run lifecycle and pinned sampling per catalog model. → `backend-internals.md` § LLM billing internals
- `ATL_STRIPE_TEST_BILLING_ENABLED` (strict opt-in) + `STRIPE_SECRET_KEY` (`sk_test_` only), `STRIPE_WEBHOOK_SECRET`, `PUBLIC_APP_URL`: Stripe **Test Mode** Credits purchases. ⚠ The purchase ledger rides `USERS_DATABASE_URL`. → `configuration.md`
- `CREDITS_METERING_ENABLED` / `DEFAULT_CREDITS`: SUPERSEDED flat quota (`domain/entitlements/credits.py`) on no request path; live billing is `domain/credits/`. Do not re-wire it.

**Databases.** The three `*_DATABASE_URL` are independent optional Postgres URLs (never one `DATABASE_URL`; no fallback between them except the Robinhood connection store). Unset = ephemeral SQLite, wiped every deploy. Set each in the Render dashboard **before** merging code that needs it. Shared rules → `configuration.md`
- `DATABASE_PATH` (default `dashboard/storage/data/backtest.db`): reset to the committed seed on every prod deploy (Prod deploy reality). Sole home of `protocol_runs`/`protocol_steps` and `idempotency_keys`, and of run history unless `AGENT_RUNS_DATABASE_URL` is set. Never set it in prod before a disk exists (an empty DB loses the seed runs).
- `USERS_DATABASE_URL` (pooled `-pooler` URL): accounts and sessions (`users.py::_build_user_store`), the Credits store (Stripe purchases), stored BYOK keys and analytics; the Robinhood connection store prefers it over `CONTENT_DATABASE_URL`.
- `CONTENT_DATABASE_URL`: agents, agent versions, strategies, `user_portfolios`, hosted-runtime credentials and research runs. Unset, a deploy wipes every agent and invalidates every agent API key.
- `AGENT_RUNS_DATABASE_URL`: run history (`agent_runs` and its child tables, via `PostgresBacktestDatabase`) and the trace store (`domain/traces/repository.py`). `idempotency_keys` stays on local SQLite on purpose (hot per-step path). → `configuration.md`

**Capacity and workers**
- `DEFAULT_MAX_CONCURRENT_BACKTESTS` (default 5): concurrent protocol runs for an account with no `user_entitlements` row, i.e. every account (nothing seeds rows). Lowering it throttles all multi-agent users at once; only per-account admin edits undo it.
- `MAX_ACTIVE_DASHBOARD_BACKTESTS` (default 5; 0 disables): server-wide cap on concurrent `POST /backtest/run` subprocesses, chiefly the LLM spend bound. → `configuration.md`
- `MAX_LEGACY_ACTIVE_PER_SESSION` / `MAX_LEGACY_ACTIVE_GLOBAL` (5 / 50; 0 disables): 429 caps on the unauthenticated legacy `/api/v1/backtest/*`; bare `int()`, so junk kills boot. → `configuration.md`
- `ATL_BACKTEST_WORKER` (`1`): set only by `run_backtest_background` in a backtest child's env, never by an operator; Postgres twins skip constructor DDL there via `db_url.init_schema_unless_worker`. → `configuration.md`
- **Two-clock contract**: read backtest progress `phases[]` durations (`duration_seconds`; `starting` excepted); never difference `started_at`/`ended_at`. → `backend-internals.md` § Backtest progress phases and the two-clock contract
- `ANALYTICS_DAILY_JOB_INTERVAL_SECONDS` (default 300): wake interval of the analytics daily-facts worker, which has its own thread, not the reaper. → `configuration.md`

**Leaderboards**
- `LEADERBOARD_DAILY_REFRESH_SECRET`: header `X-Leaderboard-Refresh-Secret` for `POST /api/v1/leaderboard/daily/refresh` and `POST /api/v1/leaderboard/live/refresh` (202) and `GET /api/v1/leaderboard?refresh=true` (or an admin session). On the POSTs, unset or wrong = 401, never 503 (a caller must not learn whether it is armed); the GET without secret or admin = 403. ⚠ `/daily/refresh` defaults `deploy_models=true` (bills every competition LLM); `/live/refresh` defaults false. `.github/workflows/daily-leaderboard.yml` keeps its `schedule:` commented out on purpose; the active nightly is `.github/workflows/live-leaderboard.yml`, whose LLM spend is gated by `LIVE_LEADERBOARD_DEPLOY_MODELS`. Set the secret in Render AND as a repo secret. → `configuration.md`
- `LEADERBOARD_DAILY_AUTO_DEPLOY` (**strict opt-in; spends money**): when truthy, the public `GET /api/v1/leaderboard?period=daily` and the boot hook (`init_daily_leaderboard`) may start a billable `deploy_model_run` for every competition LLM entry. Never restore the old "on whenever `RENDER` is unset" default (it armed every Docker image, fork, self-host and test run), nor arm it to refresh the daily board (unrefreshed on purpose). Live deploys: `LIVE_LEADERBOARD_DEPLOY_MODELS`. → `configuration.md`
- `LIVE_LEADERBOARD_DEPLOY_MODELS`: a GitHub repository variable, not a Render env var. `.github/workflows/live-leaderboard.yml`'s nightly (22:30 UTC Mon–Fri) sends `deploy_models=true` only when `vars.LIVE_LEADERBOARD_DEPLOY_MODELS == 'true'`, billing `COMMONSTACK_API_KEY` per `LIVE_MODEL_IDS` model (capped by `LEADERBOARD_MONTHLY_BUDGET_USD`); else baselines only. `true` since 2026-09-29 (`gh variable list`).
- `LEADERBOARD_MONTHLY_BUDGET_USD` (default 50; **`0` blocks every billable live deploy, it is not "off"**): the Live board's monthly model-spend hard stop (`domain/leaderboard/live_budget.py`); to lift it set a large number (junk falls back to 50). Its ledger survives `--clear` on purpose. → `configuration.md`

**Auth and mail**
- `ADMIN_BOOTSTRAP_SECRET` (>=32 chars, else treated as unset): one-shot `POST /api/admin/bootstrap` promotes the signed-in caller while no admin exists; unset, weak and wrong all answer 403 (`api/routers/admin_users.py`).
- `BREVO_API_KEY` + `ACCOUNT_EMAIL_FROM` (both required; optional `ACCOUNT_EMAIL_FROM_NAME`): transactional mail. Unset, the email-change and forgot-password send routes answer 503. → `configuration.md`
- `AUTH_FORGOT_*_MAX` / `AUTH_FORGOT_*_WINDOW_SECONDS`: forgot-password gates (defaults and rationale in the `api/auth.py` limiter block); `_MAX=0` disables one.

## Architecture

Pipeline: **backtest → store → API → dashboard** (store per the Databases bullets). Layering: `api/` → `domain/` → `infrastructure/`, with `execution/` as glue (the package contract above).

- **`api/`**: `api/router.py` mounts `api/routers/*` under `/api`. `app.py` mounts some routers **unprefixed** (`/paper/*`: `test_paper_routes_stay_outside_api_prefix`; `/health`, `/ticker`, `/backtest/*`, `/runs*`, `/compare`, `/config/*`, `/admin/*`) and defines no API routes (`test_app_defines_no_backend_api_routes`). **New endpoint:** add `api/routers/<x>.py`, `include_router` it in `api/router.py` (v2: `api/v2/router.py`). `/api/*` does its own auth; other paths need a UUID `X-Session-Id` unless `middleware.is_exempt` or `/paper/*` covers them. A new top-level prefix needs a rewrite and a slot in the `no-store` header rule (`dashboard/frontend/vercel.json`). Sync-I/O handlers are plain `def`, never `async def` (it stalls every request; list new modules in `test_event_loop_threadpool.py`).
- **`domain/`**: business logic by area (`runs/` = protocol, `backtesting/`, `leaderboard/`, `agents/`, `credits/`, `model_providers/`, `traces/` = agent-trace store, which `backtesting/decision_tape.py` writes through, ...). `entitlements/` is NOT wired (metering is `credits/`); `trading/` is **not live trading** (fill/valuation helpers; `paper_session` backs `/paper/*`).
- **`execution/`**: v2 backends binding domain engines to `/api/v2` (`backtest_backend.py`; `paper_backend.py` is a **stub**). It sits at the backend root, not in `domain/`, because it imports `api.v2.models`/`api.v2.errors`, its only allowed `api/` imports (`test_execution_layer_imports_only_the_v2_contract_from_api`). `robinhood_live_service.py` is the **real-money** Robinhood path (sends orders only if `ROBINHOOD_EXECUTE` is truthy; each order capped by `ROBINHOOD_MAX_ORDER_USD`, default 25), **switched off** by `ROBINHOOD_LIVE_ENABLED = False` (`domain/backtesting/constants.py`; real capital is out of scope). Its routes stay mounted and imported on purpose: do not delete or comment them out.
  - `execution/` Robinhood switch: per-route off-state behaviour and the RESTORE CHECKLIST (clear `live_trading_enabled` first, flip the constant, restore copy, docs and tests). → `backend-internals.md` § Robinhood live switch (`execution/`)
- **`infrastructure/`**: external adapters: `llm/` (the billed `execution/` layer, `backtest_harness`, `validator`, `http_policy`, `providers/`), `market_data/` (Alpaca bars, `bar_cache`, iFinD, vnpy), `brokers/`, `ai_hedge_fund/`, `email/` (Brevo).
- **Backend-root modules**: `database.py` (+ `database_postgres.py`, `db_pool.py`, `db_url.py`), `paths.py`, `middleware.py` (sessions + CSP), `users.py`, `llm_integration_example.py` (reference safe-LLM pattern), `integrations/` (Discord bot, news sentiment). `engines/` and `services/` are deleted shims (`_DELETED_SHIMS` keeps them non-importable).
- **Mounted surfaces outside the backtest/protocol core** bypass the `MAX_ACTIVE_DASHBOARD_BACKTESTS` slot ledger: **Trading Algo** (`/api/algo/*`, `domain/backtesting/algo_service.py`: one server-wide subprocess of `dashboard/scripts/backtest_custom_algo.py`, operator-billed) and **Research agents** (`/api/v1/research`: proxied with `RESEARCH_SERVICE_TOKEN`, 60-second sweeper). iFinD is a data source of `POST /backtest/run` (`ifind_ashare`); non-US markets are out of scope.
- **Persistence**: `database.py`'s `db` is SQLite over `DATABASE_PATH`, or `PostgresBacktestDatabase` when `AGENT_RUNS_DATABASE_URL` is set. Every dual-backend store is a SQLite / `*_postgres.py` **twin pair** registered in `test_store_twin_parity.py::_TWINS`. Local runs use the SQLite twin, so a dialect mix-up fails on Postgres prod alone: **construct `ValueAnalyticsStore`/`PostgresValueAnalyticsStore` only through `build_value_analytics_store()`**. The one dual-backend store outside `_TWINS` is `domain/agents/research_store.py` (inline `_PostgresResearchStore`, `CONTENT_DATABASE_URL`; read-by-name checked by `test_postgres_rows_read_by_name.py`). `RunStore` (`domain/runs/repository.py`) has no Postgres twin. **Changing a store:** edit both twins, repeat each lazy `ADD COLUMN IF NOT EXISTS` in the Postgres twin, read rows by column name (`dict_row`), register new pairs in `_TWINS`, `_DUPLICATED_BODIES` and `test_backtest_worker_schema_skip.py::_TWINS`, and run `@pg_only` locally.
  - Persistence detail: the twin-parity axes (incl. `_DUPLICATED_BODIES`), WAL sharing, and analytics tables and retention (`user_daily_facts` 180 days, then rolled up; no snapshot tables). → `backend-internals.md` § Persistence: twin parity and analytics tables
- **Frontend**: `dashboard/frontend/` serves every UI: landing at `/` (`index.html` + `assets/`), the no-build vanilla-JS + Chart.js dashboard at `/app` (`app.html`, `app.js`, `js/*.js`), the admin console at `/admin` (`admin.html`) and `strategy.html`.
  - `app.html` script tags carry `?v=N` cache-busters that tests pin with script order: bump tag and tests together. `app.py` serves frontend files through explicit routes (generic only under `/js/`, `/market-events/`, `/assets/`, `/images/`; `/data/` is an allowlist): a new top-level file needs one.
  - **Landing:** source `dashboard/landing/` (React, Vite, Tailwind 4); its build is **hand-copied** into `frontend/assets/`, so editing `landing/src` alone changes nothing in prod. `frontend/index.html` is not build output: keep its hand-written auth layer (`#landingAuthModal`). Follow `dashboard/landing/README.md` (`test_frontend_bundle_integrity.py`).
  - Frontend JS uses a root-relative API base, never the Render origin (`test_frontend_api_base.py`). CORS allowlist: `ATL_FRONTEND_ORIGINS`; CSP lives in both `middleware.py` and `vercel.json`.
- **Paths** (`dashboard/backend/paths.py`): on-disk locations (`REPO_ROOT`, `DATA_DIR`, `BAR_CACHE_DIR`, ...); the `DATABASE_PATH` override is resolved in `database.py`.
- **Runtime:** Python 3.13. The AI Hedge Fund runs in a separate 3.12 venv (`AI_HEDGE_FUND_PYTHON`, `requirements-ai-hedge-fund.txt`) behind a JSON subprocess boundary, because its numpy pin has no 3.13 wheels: never import it in-process.

### Capital Allocation is scoped to the caller, not just the account

`PortfolioService` sums agent sleeves over an `AgentScope` (owner's agents + the calling browser's unclaimed guest agents), so "Allocated to Agents" matches the My Agents legend (`GET /api/v1/agents`). Every router call into `portfolio_service` must pass `scope=AgentScope.from_owner_context(ctx)` (`api/routers/portfolio.py::_scope`); the default `EMPTY_SCOPE` is account-only (SDK, cron, tests). This makes the figures agree; it is NOT an allocation ceiling (`_reconcile` reports any overage). Pinned both ways by `test_portfolio_scope_sync.py`.
- Deliberate exceptions: `user_portfolios.cash_available` and starter provisioning stay account-scoped, and the agent grid's page size is measured off the CSS column ladder. → `backend-internals.md` § Capital Allocation scope

### Baseline strategies (registry pattern)

Subclass `BaselineStrategy` (`key`) and add it to `_STRATEGY_CLASSES` in `dashboard/backend/domain/leaderboard/strategies/registry.py`; an entry's config `strategy` selects it.

**H6 leaderboard integrity guard.** An LLM entry publishes only if the model drove >= `MIN_LLM_DECISION_COVERAGE` (0.95, `domain/leaderboard/service.py`) of `decision_steps`; otherwise `_reject_if_llm_fallback` raises `LeaderboardFallbackError` (every insert path; per segment on the Live board). Only `allow_fallback=True`/`--allow-fallback` waives it, never HTTP. Coverage keys on `PortfolioManager.llm_decisions` (steps the model genuinely drove; keep its two write sites in `portfolio_manager.py` the only ones), NOT `llm_calls` (a billing counter that also ticks on replies that fell back to rules). Pinned by `tests/domain/leaderboard/test_deploy_guard.py`.
- Repeat LLM runs publish their median plus `sample_band`; `_vetted_pool` (`service.py`) drops other-seed, other-days and no-equity repeats. → `backend-internals.md` § Repeat LLM runs: median and sample band

### Two leaderboards, and what `live` does *not* mean

Both rank a curated roster (`dashboard/config/leaderboard.json`); neither takes user entries (no submission route in `api/routers/leaderboard.py`; Agent API v2 runs are ranked separately at `GET /api/v2/leaderboard`). Don't write copy that implies otherwise.
- **Competition Leaderboard** (`?period=contest`, the acquisition hook): one fixed historical window (`start_date`/`end_date` in that config), built by `service.get_leaderboard`.
- **Live Trading Leaderboard** (`?period=live`; the decided rename to "Live Leaderboard" has not landed): the current New York calendar month (seasons = calendar months, `docs/superpowers/specs/2026-10-14-atl-direction.md`), in `domain/leaderboard/live.py`, session `leaderboard-live`, roster = baselines + `LIVE_MODEL_IDS`.
- `?period=daily` and `POST /daily/refresh` still exist; the daily tab is gone and its cron is paused.

**Live GET is read-only (spend control).** `get_live_leaderboard` only reads stored freeze and ledger rows: it never fetches bars, recomputes, deploys models or schedules a refresh. Only `refresh_live_leaderboard` writes, via `POST /api/v1/leaderboard/live/refresh` or `dashboard/scripts/refresh_live_leaderboard.py`. Never add compute or deploys to a GET path (`test_live_api_get_is_read_only`, `test_get_live_never_deploys_models`).
- Board did not move overnight? A 202 only means enqueued, the cron fires late, and failures are log lines. → `backend-internals.md` § Live board refresh

### LLM safety boundary

On backtest and leaderboard paths a model answer can trade only inside the run's simulated portfolio; the one indirect channel is a post-trade reply rewriting later decision prompts. **That does not come from `validate_llm_response`** (`infrastructure/llm/validator.py`; only `llm_integration_example.py` and tests call it), so never cite it as the boundary. It holds because no request sends `tools`, only text blocks are read, parsing is JSON-or-nothing, and limits are enforced in code after parsing. Never add tools, web access or function calling to an LLM request, and do not loosen these parsers. (The off Robinhood path turns answers into real orders: `_risk_gate_orders`, `_review_blocks_order`.)
- No LLM request passes `tools`/`tool_choice` (`request_trading_decision`, `infrastructure/llm/backtest_harness.py`); `llm_integration_example.py` shows `tools=` only inside an anti-pattern string.
- Parsing is JSON-or-nothing (`parse_llm_response` slices the first `{` to the last `}`, else `None`); an unusable reply costs differently in billed, strict and non-strict runs. → `backend-internals.md` § LLM reply parsing: JSON-or-nothing
- The portfolio manager enforces order limits after parsing (symbol universe, action count <= universe size, `MAX_ORDER_SHARES` 10k, cash bound, confidence >= 0.3). The per-constraint table lives only in `dashboard/backend/SECURITY.md` (*Exemption: the backtest engine's LLM loop*); fix it there.
- Post-trade steps (`run_post_trade_analysis`, `infrastructure/llm/pipeline_runner.py`) return `prompt_patches` that replace decision-step prompts for the rest of the run (`apply_prompt_patches`), so one model reply becomes instruction text for every later bar. No limit may depend on what a decision prompt says.
- The Trading Algo backtest (`/api/algo/execute` → `dashboard/scripts/backtest_custom_algo.py`) is a second, weaker loop outside these guarantees: its own parsing, at most 8 `DJIA_30` actions, no `MAX_ORDER_SHARES` (a buy is bounded only by cash). Harden it onto the shared helpers before citing the bullets above for it (`SECURITY.md`, *Not covered*).
- External agents' decisions (protocol and v2 via `external_run_service`, plus the AI Hedge Fund adapter) go through `validator.py`'s `parse_actions_payload` and `actions_to_executable`; v2 also pre-validates with `validate_actions` (`api/v2/models.py`).

## Merge & branch discipline

**`main` is gated by the GitHub ruleset `main protection` (ID 26155796, since 2026-10-29), and the gate has a bypass.** The live copy is the authority (`gh api repos/Open-Finance-Lab/AgenticTrading/rulesets/26155796`). As last recorded: one approving review (a new push dismisses it; the last pusher may approve) and CodeQL results with no *new* `error`-severity or >= high security alert (an alert counts only if every line it flags is in the PR diff, so alerts already on `main` never block); force pushes and deleting `main` are blocked. **No required CI checks** (an approved PR merges over a red `Backend tests`), no CODEOWNERS. Only org/repo admins bypass (`gh pr merge --admin`, PR mode only); nobody pushes to `main` directly. Treat every open PR as mergeable right now by someone who has not read your plan.
- **CI map** (`.github/workflows/ci.yml`): `Backend tests` (Python 3.13, Postgres 18 service, the CI pytest form) alone gates the deploy hook; `Packaging (agentictrading) tests`, `Landing frontend checks` (node 20: `npm ci`, `typecheck`, `build`), `Dependency pins` and `Dependency audit (pip-audit)` do not. Never push `v*` tags (`publish-pypi.yml` fails).
- **First-time fork contributors** (repo setting `first_time_contributors`): their CI and CodeQL runs sit at `action_required` until a maintainer approves them, and the ruleset has no CodeQL result to read until then: approve the runs, do not bypass. Review is the second wait; a returning contributor's runs start on their own.
- Every PR to `main` needs a CodeQL run on its current merge commit, or it cannot merge without a bypass. Never add a `paths:` filter to `.github/workflows/codeql.yml`'s `pull_request` trigger (`branches: [main]` is fine). A PR retargeted to `main` gets no run (the `edited` event is skipped by default): push a commit or close and reopen it; do not use `--admin`.
- What CodeQL scans is what the gate covers: narrowing the query suite in `.github/codeql/codeql-config.yml` (`security-and-quality`) narrows the gate, and every `paths-ignore` entry (`orchestration`, `dashboard/frontend/assets`, `**/dist`, `**/node_modules`) is ungated. Do not add a directory there to cut noise.
- Never push follow-up work to a branch whose PR is already merged; cut a new branch. Commits behind a merged PR orphan silently. Check first: `gh pr list --head <branch> --state all`.
- To hold a PR, publish that where GitHub shows or enforces it: open it as a draft or add a `blocked` label, and put an imperative in the first line of the body ("DO NOT MERGE until X ships"). A comment is not a gate, and body text explaining why early landing is safe reads as "merge me".
- Never record in notes or memory that a merge was sequenced deliberately unless a session verified and pressed it: `gh api repos/Open-Finance-Lab/AgenticTrading/pulls/N --jq '.merged_by.login'`.

## Fail-closed is not fail-visible

A fallback that keeps output looking healthy hides a total break. Case: when FinSearch renamed fields, the news adapter's (`dashboard/backend/integrations/news_sentiment.py`) fallback served plausible output for hours on per-item warnings alone. It now logs ERROR at the wholesale-drift boundary (`_alarm_if_all_dropped`) and the panel escalates to `status: degraded`; the backtest path (`load_news_sentiment`) is still log-only, and a 404 deliberately logs nothing (no artifact yet is normal).
- When adding a fallback, ask what distinguishes *absent* from *broken*. If nothing does, log ERROR at the wholesale-drift boundary; a per-item warning cannot report a total contract break.
- Never build an upstream's fixture from your own adapter's field names (it tests the mapper against itself and drifts with the code). Pin the shape from a real recorded response: `dashboard/backend/tests/fixtures/{items,signals}-wire-fixture.json`.
- Mocked tests cannot detect a cross-repo producer rename (the producer is mocked); only a canary against the live endpoint can. More mock tests are not coverage of this seam.

## Gotchas

- The committed `dashboard/storage/data/backtest.db` holds the seed runs `dashboard/config/defaults.json` points at. Importing any store module (`database.py`, `users.py`, `domain/runs/repository.py`, ...) runs `CREATE TABLE IF NOT EXISTS` against `DATABASE_PATH`, so a local run on the default path mutates the tracked file: use `run_local_safe.sh`, never commit those mutations, and update `defaults.json` if you regenerate the DB.
- **A backtest's `end_date` is inclusive; every provider reads `end` as half-open.** Convert only through the helpers in `infrastructure/market_data/provider.py`: `settled_exclusive_end()` for backtests; plain `exclusive_end()` only for the rolling daily board and the default window. A raw `end_date` handed to a provider drops the last day (a one-day run gets no bars); the settled form also stops at today (Alpaca serves the forming bar). Pins: `test_engine_window_end.py`.
- Indicator warm-up pad: the fetch starts 30 calendar days before `start_date` and the pad is split off before anything trades; evidence in `agent_runs.metadata.indicator_warmup`. → `backend-internals.md` § Indicator warm-up pad
- **Never hand-edit `requirements.txt` or `requirements-test.txt`:** uv compiles each from its `.in` (the whole tree, transitives included). Change the `.in`, re-run the `uv pip compile` command in its header, commit both; `--upgrade-package <name>` moves one transitive. CI's `Dependency pins` job fails on any diff; the `Dockerfile` installs `--no-deps` then runs `pip check`, so a missing pin fails the build instead of floating.
- `discord.py` (the Discord bot) is an **optional** dep in `requirements-discord.txt`, not core `requirements.txt`: `pip install -r requirements-discord.txt` (pulls in core too). The bot tests `importorskip('discord')`; `test_discord_wiring.py` pins the file and this mention.
- `vnpy` (`vnpy_simulation` data source) is **optional** (`requirements-vnpy.txt`); CI installs core `requirements.txt` only. A test importing an optional dep at module scope must `importorskip` it: an unguarded import is a *collection* error that aborts the whole session (0 tests run, `deploy-prod` never fires). For an import-safe module, gate cases with `skipif(importlib.util.find_spec("vnpy") is None)`.
- ~50 `test_*.py` modules run frontend JS under `node -e` (lifted from `app.js`/`js/*.js` via `tests/_frontend_source.py`, admin pages via `_admin_dom_stub.py`), the only JS-behaviour coverage the dashboard has. Without `node` on `PATH` they all skip silently.
- **Prod deploy reality vs `render.yaml`** (documentation only; prod does not sync from it). The live service (`srv-d7lbmpjbc2fs73bcr6t0`) builds `./Dockerfile` (`env: docker`), Standard `1c-2g` since 2026-09-11. **It has no `/data` disk (`disk: null`) and `DATABASE_PATH` is unset**, so every redeploy resets SQLite to the committed seed; only the three `*_DATABASE_URL` stores (accounts, agents, runs) are durable. RAM headroom (~1.1 GB) is instance-wide, not per backtest child.
- **`test_deleted_shim_is_not_importable[...engines|services]` failing locally with `DID NOT RAISE ModuleNotFoundError` is stale bytecode, not a regression.** Untracked leftover `dashboard/backend/{engines,services}/__pycache__/` resolve as PEP-420 namespace packages; CI is clean. Fix: `rm -rf dashboard/backend/engines dashboard/backend/services`.
- **Everything passed to `register_reaper_sweep` runs inline on the one reaper thread, every `RUN_REAPER_INTERVAL_SECONDS` (default 60; `domain/runs/service.py`).** No per-sweep interval exists, so per-user work multiplies by every tick, and the same pass fails any run whose heartbeat is older than `RUN_HEARTBEAT_STALE_SECONDS` (300): a slow sweep can kill live runs. Heavy periodic work gets its own thread, like `domain/analytics/daily_job.py` (`test_daily_job.py`).
- `tests/conformance/` pins known engine defects as strict xfails (`known_failures.json`), so fixing engine behaviour turns them red by design. Don't loosen or delete them: update `PREDICTIONS_*` in `cases.py`, re-record with `CONFORMANCE_UPDATE_KNOWN_FAILURES=1 pytest dashboard/backend/tests/conformance/test_conformance_current_engine.py`, review the JSON diff.
