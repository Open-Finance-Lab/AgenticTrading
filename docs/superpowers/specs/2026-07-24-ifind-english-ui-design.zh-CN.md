# iFinD A 股界面全英文化设计

## 背景

ATL 的 iFinD A 股数据链路已经完成并通过真实数据回测，但 iFinD 回测入口仍包含中文标签和中文公司名称。目标用户包含不懂中文的海外用户，因此所有用户可见的 iFinD 文案必须使用清晰、可识别的英文。

本次改动只更换界面上的“招牌和商品标签”，不调整 iFinD 数据接口、股票池、OHLCV 转换、规则 Agent 或回测计算。

## 目标

1. iFinD 回测界面不再显示中文。
2. 每只股票同时显示国际通行英文公司名和证券代码。
3. 数据源名称、股票池标题和运行记录徽标使用一致的英文术语。
4. 较长的英文公司名称在桌面和移动布局中不溢出或遮挡其他内容。
5. 自动化测试阻止中文可见文案重新进入 iFinD 前端区域。

## 非目标

- 不实现中英文切换或通用国际化框架。
- 不翻译代码注释、测试说明、日志或中文设计文档。
- 不修改股票代码、固定六股股票池或 60 分钟周期。
- 不修改 iFinD API 请求、返回格式、认证方式或 Token 管理。
- 不修改 Agent 决策、模拟成交、基准策略或回测指标。

## 英文文案映射

| 使用位置 | 当前文案 | 英文文案 |
| --- | --- | --- |
| 数据源选项 | `iFinD A股（60分钟）` | `iFinD China A-Shares (60 min)` |
| 数据源徽标 | `iFinD A股 · 60m` | `iFinD China A-Shares · 60m` |
| 股票池标题 | `A股代表6只` | `6 Representative A-Shares` |
| `600519.SH` | `贵州茅台` | `Kweichow Moutai` |

证券代码继续作为每个公司的第一识别信息或紧邻公司名展示。即使英文名称存在缩写或市场惯用写法，代码也能消除歧义。

## 实现范围

### 静态页面

更新 `dashboard/frontend/app.html` 中的股票池标题和六家公司名称。保持现有 DOM 结构、可访问性属性和元素 ID 不变，避免影响 JavaScript 行为与测试定位。

### 动态页面文案

更新 `dashboard/frontend/app.js` 中动态创建的数据源选项、运行记录来源徽标和结果来源标签。相同概念必须复用同一套英文词汇，不允许一个位置使用 `A Share`、另一个位置使用 `Chinese stocks`。

### 样式

优先沿用现有响应式网格。只有在实际浏览器验证发现长公司名溢出时，才对 iFinD 股票项增加换行或最小宽度约束，不进行无关视觉重构。

## 数据流与错误处理

文案替换不进入数据流。浏览器仍提交：

- `data_source=ifind_ashare`
- `universe=a_share_demo_6`
- `timeframe=60m`

后端仍返回相同字段，前端仅改变这些内部值对应的展示文本。现有功能开关关闭、Token 缺失、API 失败和回测失败处理保持不变，因此不新增运行时翻译错误或回退分支。

## 测试与验收

1. 更新 iFinD 前端测试，断言全部目标英文文案存在。
2. 断言 iFinD 用户可见区域不再包含原有中文文案。
3. 运行 iFinD 前端、市场数据功能和回测接口相关测试。
4. 运行完整后端测试集，确保文案修改没有破坏页面合同。
5. 启动 ATL，在桌面和移动视口检查回测页面：数据源选项、固定六股列表和运行来源徽标均为英文，长名称不溢出。
6. 验证 Git 差异不包含 `.env`、Token、本地数据库或日志。

## 停止条件

- ATL 前端源码中不再存在本次列出的中文可见文案。
- 六家公司的英文名称与证券代码正确配对。
- 自动化测试和浏览器检查通过。
- iFinD 数据与回测行为相较改动前保持一致。
