# iFinD 全股票池 Agent/LLM 与回测资金校验设计

## 1. 背景

ATL 当前已经支持使用 iFinD 真实 A 股 60 分钟行情运行模拟回测，并注册了两个固定股票池：

- `A-Share Demo 6`
- `CSI 300 Sample 20 (2026 H2)`

现有实现只允许 `A-Share Demo 6` 在规则决策和 LLM 决策之间切换；
`CSI 300 Sample 20 (2026 H2)` 在前端和后端都被限制为规则决策。因此用户选择
20 股股票池后，Model 控件会被禁用，不能选择 ATL 已有 Agent/LLM。

回测初始资金输入框还存在独立的 HTML 原生校验错误：输入框同时使用
`min="1"`、`step="100"` 和默认值 `value="1000"`。浏览器据此只接受
`1 + 100n`，导致 ATL 的合法默认资金 `1000` 被判定为 step mismatch，最近的有效值
反而显示为 `901` 和 `1001`。JavaScript 提交逻辑和后端实际都允许任意
`0 < initial_capital <= 10000` 的金额。

## 2. 目标

1. 两个 iFinD A 股股票池都支持 `rule_based` 和 `llm`。
2. 两个股票池默认都使用 `rule_based`，避免用户在未主动选择模型时产生 LLM 调用。
3. 两个股票池都可以选择 ATL Model 控件中已有的 9 个模型。
4. 用户显式选择模型后必须运行严格 LLM 路径；调用失败时不得静默退回规则决策。
5. 初始资金 `1000` 必须通过浏览器、前端提交逻辑和后端 API 的一致校验。
6. ATL 继续只执行历史模拟回测，不接券商、不发送真实订单。

## 3. 非目标

- 不新增模型、LLM Provider 或 API 凭证类型。
- 不改变 iFinD 行情获取、OHLCV 转换或 60 分钟数据粒度。
- 不增加用户自定义 A 股股票池。
- 不实现 A 股实盘交易或券商账户连接。
- 不在本轮补齐 T+1、100 股整手、涨跌停和停牌撮合等 A 股专用制度。
- 不把规则模式改成 LLM 默认模式。

## 4. 方案比较

### 4.1 采用：统一 Market Profile 能力并修正资金步长

前端和后端的两个 A 股 Profile 都声明允许 `rule_based` 与 `llm`，同时保留
`rule_based` 为默认值。初始资金输入框改为 `min="1"`、`step="1"`、
`max="10000"`，与现有 JavaScript 和后端“任意正整数、上限 10,000”的规则一致。

优点是改动范围小、能力声明明确、前后端一致，并能复用已经完成验证的严格 A 股 LLM
链路。缺点是 20 股回测的输入规模、调用成本和执行时间通常高于 6 股回测，但这是用户
主动选择模型后的预期行为。

### 4.2 不采用：只在前端解锁 20 股 Model 控件

这种方案页面上可以选择模型，但后端 Profile 仍会拒绝
`decision_source=llm`，造成“看起来能选、实际不能跑”的错误状态。

### 4.3 不采用：继续限制资金为 100 的倍数

可以改成 `min="100"`、`step="100"`，但这会新增“只允许整百金额”的业务规则，
并与后端当前接受任意正金额的行为不一致。`step="any"` 也不采用，因为前端最终会把
金额取整，允许输入小数反而容易误导用户。

## 5. 能力与默认值

两个 Profile 的目标配置一致：

| 股票池 | 允许的决策来源 | 默认决策来源 |
| --- | --- | --- |
| `A-Share Demo 6` | `rule_based`, `llm` | `rule_based` |
| `CSI 300 Sample 20 (2026 H2)` | `rule_based`, `llm` | `rule_based` |

后端 Market Profile 是 API 授权边界，前端配置负责正确展示相同能力。两端必须同时更新，
但后端仍是最终校验者，不能仅依赖浏览器传入的 `decision_source`。

## 6. 用户流程

```text
选择 iFinD China A-Shares
  -> 选择 Demo 6 或 CSI 300 Sample 20
  -> Model 默认显示 Rule-based
  -> 用户保留 Rule-based：不传实际模型配置，不调用 LLM
  -> 用户选择任一模型：提交 decision_source=llm、model 和 pipeline
  -> 后端按所选 Profile 校验股票白名单
  -> 使用同一批 iFinD OHLCV 进入严格 LLM 回测
  -> 保存回测曲线、交易记录、决策来源和模型元数据
```

切换股票池时，Model 控件重新回到 `Rule-based`。这样不会把用户在另一个股票池中选择的
付费模型隐式带入新回测；用户需要再次明确选择模型。

## 7. 严格 LLM 行为

本轮复用现有 A 股严格 LLM 路径，不创建第二套 Agent 引擎：

- 显式模型选择解析为 `decision_source=llm`。
- 请求必须携带所选模型和当前 Agent Pipeline。
- LLM 只能对当前 Market Profile 注册的股票代码产生动作。
- 缺少凭证、Provider 调用失败、响应无法解析或动作不合法时，运行明确失败。
- 严格 LLM 运行不得改用规则 Agent 继续生成一条看似成功的回测曲线。
- `Rule-based` 请求不携带生效的模型或 Pipeline，且 `llm_calls=0`。

## 8. 初始资金规则

回测资金输入框使用：

```text
min=1
step=1
max=10000
default=1000
```

用户可输入 1 到 10,000 之间的整数。前端继续拒绝非数字、零、负数和大于 10,000 的
金额；后端继续执行相同边界校验。资金只影响本次历史模拟回测，不改变 Agent 的
Allocated Capital，也不影响 Paper Trading 账本。

## 9. 错误处理

- 未知 A 股股票池：后端返回受控的 Profile 校验错误。
- 不支持的决策来源：后端拒绝请求，不猜测或降级。
- LLM 凭证缺失或调用失败：严格 LLM 回测失败并返回明确错误。
- 初始资金不在范围内：浏览器和前端尽早提示，后端仍做最终校验。
- iFinD 行情失败或不完整：沿用现有失败行为，不使用模拟数据或其他数据源顶替。

## 10. 测试设计

### 10.1 Profile 与 API

- 两个 A 股 Profile 都允许 `rule_based` 和 `llm`。
- 两个 Profile 在未指定决策来源时都解析为 `rule_based`。
- 两个股票池的 `decision_source=llm` API 请求都被接受并进入严格 LLM 配置路径。
- 未知 Profile 和未知决策来源仍被拒绝。

### 10.2 前端

- Demo 6 和 Sample 20 的配置都声明 `['rule_based', 'llm']`。
- 选择任一 A 股股票池时 Model 控件均可用，并显示规则项和 9 个现有模型。
- 切换股票池后 Model 重置为 `Rule-based`。
- 规则请求不提交生效的模型/Pipeline；LLM 请求提交所选模型/Pipeline。
- `backtestInitialCapital` 的默认值 `1000` 满足 HTML 原生有效性。
- `1000` 能进入回测请求；`0`、负数和超过 `10000` 的金额继续失败。

### 10.3 回归与端到端

- 使用假的 iFinD 和假的 LLM Provider 跑通 Sample 20 严格 LLM 全链路。
- 证明 LLM 决策只能使用 Sample 20 白名单代码。
- 证明 LLM 失败不会生成规则回退结果。
- 两个股票池的规则回测仍然完成，且 `llm_calls=0`。
- 运行相关聚焦测试和完整测试套件。
- 在浏览器中验证两个股票池的 Model 控件、默认状态和 `1000` 元资金有效性。

真实付费 LLM 凭证不是合并本次功能的硬性前提；离线假的 Provider 必须覆盖完整控制流。
如果本机存在 ATL 能自动选择的真实 Provider 凭证，可额外执行一次真实 LLM smoke test，
并在提交说明中如实记录结果。

## 11. 验收标准

1. Demo 6 和 CSI 300 Sample 20 都可以选择 `Rule-based` 或任一现有模型。
2. 重新选择任一 A 股股票池后默认都是 `Rule-based`。
3. Sample 20 的 LLM 请求不再被前端禁用或被后端 Profile 拒绝。
4. 显式 LLM 失败不会静默产生规则回测结果。
5. 初始资金 `1000` 不再出现“最近有效值为 901 和 1001”的浏览器提示。
6. A 股规则回测、Demo 6 LLM 回测和既有美股行为没有回归。
7. 全部变更仍限定为模拟/回测，不产生真实交易行为。
