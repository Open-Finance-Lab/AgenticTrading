# iFinD A 股历史汇率与双币种回测设计

## 背景

ATL 已能通过 iFinD 获取 A 股 60 分钟 OHLCV 行情并运行 Agent 和等权 Buy-and-Hold 回测。当前回测页面继续使用统一的 `$1,000` 初始资金，但 iFinD 返回的是人民币计价的 A 股价格，现有回测引擎把两个没有币种信息的数值直接相加、相减和比较。

因此，当前 A 股回测中的 `$1,000` 实际被错误地当成 `¥1,000` 使用，交易记录和权益曲线却仍显示美元符号。这既影响仓位计算，也使 A 股、美股和基准之间的结果无法公平比较。

iFinD HTTP API 用户手册确认历史行情接口支持人民币和美元货币参数。实际账户验证发现 `/api/v1/edb_service` 经济数据库不向当前免费数据接口开放，但 `/api/v1/cmd_history_quotation` 可以对同一 A 股、同一日期分别返回人民币和美元历史收盘价。

使用贵州茅台 `600519.SH` 在 `2026-04-01` 至 `2026-04-03` 的真实响应验证后，人民币收盘价除以美元收盘价得到每天变化且方向正确的 USD/CNY 历史换算率。因此本设计不依赖 EDB 权限，而是从 iFinD 自身的双币种历史行情中恢复它实际使用的历史换算率。

## 目标

1. iFinD A 股行情、技术指标、模拟成交和持仓账本继续使用人民币。
2. 页面输入仍以美元为主，`$1,000` 在回测开始时按当日 iFinD USD/CNY 历史换算率换成人民币交易本金。
3. 每个 A 股交易日使用 iFinD 双币种历史行情隐含的 USD/CNY 换算率，把人民币权益换算为美元权益。
4. 现有图表、指标、排行榜和跨市场比较继续使用美元报告币种。
5. 保存人民币原始金额、所用汇率和美元换算金额，使每个结果都可审计。
6. Agent 和 A 股 Buy-and-Hold 基准使用完全相同的汇率序列。
7. 汇率缺失或无权限时明确失败，不使用固定汇率或第三方静默兜底。

## 非目标

- 不修改 Rule-based Agent 的 2% 仓位比例或 RSI/SMA 条件。
- 不强制最少买入 1 股。
- 不在本 Loop 中实现 A 股 100 股一手、T+1、涨跌停、佣金或印花税。
- 不增加真实交易或实盘下单。
- 不改变 Alpaca 和 vn.py 模式的美元回测逻辑。
- 不用固定汇率改写 iFinD 原始 OHLCV。

## 核心定义

USD/CNY 汇率定义为“一美元对应多少人民币”，例如 `7.1260`：

```text
USD -> CNY: usd_amount * rate
CNY -> USD: cny_amount / rate
```

对 iFinD A 股配置：

- 原生币种（native currency）：`CNY`
- 报告币种（reporting currency）：`USD`
- 汇率对：`USD/CNY`
- 汇率口径：iFinD 历史行情人民币价除以美元价得到的当日换算率
- 市场时区：`Asia/Shanghai`

Alpaca 和 vn.py 的原生币种与报告币种均为 `USD`，不创建汇率转换层。

## 架构

### 市场配置

`MarketProfile` 增加原生币种和报告币种。只有原生币种与报告币种不同时，回测引擎才创建汇率上下文。该判断属于市场配置，不根据证券代码或 UI 文案推测。

### 历史汇率提供者

新增独立的历史汇率协议，输入候选 A 股、日期范围并返回按上海日历日期索引的 USD/CNY 序列。iFinD 实现使用现有后端 token 对 `/api/v1/cmd_history_quotation` 发起两次相同的日线收盘价请求：

1. `Currency=RMB` 获取人民币收盘价；
2. `Currency=MHB` 获取美元收盘价；
3. 对同一证券和日期计算 `close_rmb / close_usd`；
4. 对当天多个有效证券的隐含汇率取中位数。

两次请求都显式使用日周期、不复权和空值填充，避免停牌填充或复权差异污染比值。候选证券来自本次 A 股股票池，不额外引入股票池外依赖。

每日至少需要两个证券产生有效的人民币价与美元价。所有证券的隐含汇率必须在允许的相对误差内一致；实现以中位数为中心校验离群值，不能从任意单只股票静默接受冲突结果。这样既降低四位小数价格舍入误差，也能发现供应商返回方向或货币参数异常。

该汇率代表 iFinD 历史行情实际使用的换算率。由于手册没有声明它一定等于央行中间价或可成交即期汇率，代码、metadata 和页面都不得将其标记为“央行中间价”。

查询窗口从回测开始日前额外向前取 14 个日历日，以覆盖周末和较长节假日。返回值必须满足以下条件：

- 日期可解析并按升序排列；
- 汇率是有限正数；
- 重复日期不能包含相互冲突的数值；
- 第一根 A 股 K 线之前必须至少有一个有效汇率。

### 日期对齐

每个 A 股交易日优先使用当天的 iFinD 历史换算率。当日缺失时只向前沿用最近一个有效值，绝不反向填充未来日期的汇率。

同一交易日内的所有 60 分钟 K 线使用同一个汇率。汇率只生成 USD 报告视图，不进入 Agent 的人民币市场信号、现金约束或成交决策，因此不会向交易策略泄漏未来汇率信息。

### 双币种账本

回测开始时：

```text
native_initial_capital_cny = initial_capital_usd * opening_usdcny_rate
```

`PortfolioManager` 内部的现金、持仓价值、市场信号、成交价和总权益均保留人民币数值。Rule-based 和 LLM 依据人民币价格和人民币可用现金计算股数，避免汇率变化污染 RSI、SMA、MACD 等 A 股原生技术指标。

每次记录权益时，先计算人民币账本，再按该 K 线所属日期的汇率生成美元报告视图：

```text
equity_usd = equity_cny / usdcny_rate
cash_usd = cash_cny / usdcny_rate
positions_value_usd = positions_value_cny / usdcny_rate
```

回测决策不得读取未来汇率。USD 报告视图仅用于进度、持久化、绩效计算和展示。

### Agent 与基准

Agent 与 A 股等权 Buy-and-Hold 基准共享同一个已对齐汇率上下文：

1. 两者都以相同的美元初始资金换成人民币；
2. 两者都在人民币账本中模拟买卖或持有；
3. 两者都按同一日汇率生成美元权益曲线；
4. Sharpe、最大回撤和总收益都从美元权益曲线计算。

任何一方不得使用固定汇率或不同日期的汇率，否则该次比较无效。

## 持久化合同

为了保持现有前端和排行榜兼容，已有字段继续表示报告币种 USD：

- `agent_runs.initial_equity`、`final_equity` 和 `total_return`
- `equity_timeseries.equity`、`cash` 和 `positions_value`
- `trades.price` 和 `value`

同时增加可空的审计字段：

- 权益点：`native_equity`、`native_cash`、`native_positions_value`、`fx_rate`
- 交易：`native_price`、`native_value`、`fx_rate`

旧记录和 USD 原生回测允许这些字段为空。数据库迁移必须幂等，并兼容现有新旧 trades 表结构。

每个 iFinD run 的 metadata 至少记录：

- `native_currency: CNY`
- `reporting_currency: USD`
- `fx_pair: USD/CNY`
- `fx_source: ifind_history_currency_conversion`
- `fx_policy: daily_implied_median_forward_fill`
- 用于推导汇率的证券列表和一致性容差
- 开始和结束汇率
- 使用的汇率日期范围

token、refresh token 和其他凭证不得进入 metadata、数据库、API 响应或日志。

## 前端展示

回测输入和主要绩效继续使用美元，使 A 股与美股结果可直接比较。A 股回测配置和结果补充显示：

```text
Initial Capital       $1,000.00
CNY Trading Capital   ¥7,126.00
FX Source             iFinD Historical Conversion Rate
Start FX Rate         7.1260
Final Value           $1,043.20
```

交易日志以美元报告值为主，并显示人民币原始成交值和当日汇率：

```text
BUY 600519.SH
Price: $211.20 (¥1,505.00)
Value: $211.20 (¥1,505.00)
FX: 7.1260
```

USD 原生回测继续只显示美元，不出现多余的双币种信息。0 交易空状态、短数据提示和 LLM 配置错误行为保持不变。

## 错误处理

以下情况必须停止 iFinD A 股回测：

- iFinD token 缺失、过期或无历史行情货币转换权限；
- iFinD 返回 HTTP、业务或无效 JSON 错误；
- 人民币或美元历史行情表结构无法识别；
- 同一天少于两个证券能形成有效汇率；
- 多个证券的隐含汇率超出允许的一致性容差；
- 第一根 A 股 K 线之前没有可用汇率；
- 汇率包含非数值、非有限值、非正数或冲突重复值。

面向用户的错误必须说明检查汇率指标权限、配置或日期范围。日志保留端点、日期范围和错误类型，但不得包含凭证或完整供应商响应。

不得在错误路径中使用固定 `7.10`、当前汇率、未来汇率或第三方服务继续运行。

## 测试标准

### 数学与日期

- `$1,000 * 7.00` 产生 `¥7,000` 原生初始资金。
- 股票价格和汇率都不变时，最终权益仍为 `$1,000`。
- 人民币权益保持 `¥7,000`、汇率从 `7.00` 变为 `7.10` 时，美元权益约为 `$985.92`。
- 当日汇率缺失时使用此前最近值，不允许使用后一日数值。
- 第一根 K 线前没有汇率时明确失败。

### 数据与领域

- 双币种历史行情请求、响应解析、重试、业务错误和脱敏日志都有单元测试。
- 多证券隐含汇率的中位数与一致性校验覆盖舍入、缺数和冲突响应。
- 汇率序列验证日期、数值、重复项和向前填充。
- PortfolioManager 的人民币决策状态不被 USD 报告值覆盖。
- Agent 和等权基准使用同一原生本金及汇率序列。
- 交易的 USD 值、CNY 原始值和汇率满足换算恒等式。

### 持久化与前端

- 数据库从现有 schema 幂等升级，并能读取历史 USD 记录。
- 图表、主要指标和排行榜继续读取已有 USD 字段。
- iFinD 配置显示美元本金、人民币交易本金、汇率来源及开始汇率。
- iFinD 交易日志显示 USD 主值、CNY 原始值和汇率。
- Alpaca 和 vn.py 页面不显示 A 股汇率字段。

### 回归与真实验收

- 现有后端、前端契约、Alpaca、vn.py 和 iFinD 测试全部通过。
- 使用真实 iFinD 权限完成一次 A 股回测，确认人民币价除以美元价的方向是 CNY per USD。
- 真实回测的 Agent、等权基准、权益点、交易和 metadata 都能按公式互相核对。
- 真实验收不得以 fixture、固定汇率或截图替代。

1. 用 iFinD“超级命令”验证人民币和美元历史行情协议及换算方向。
2. 实现 iFinD 双币种历史行情汇率客户端、解析器和日期对齐。
3. 扩展市场配置和双币种账本。
4. 让 Agent、进度流和 A 股基准统一生成 USD 报告视图。
5. 扩展数据库审计字段和 API 返回。
6. 完成前端双币种展示。
7. 运行单元、契约、回归和真实 iFinD 浏览器验收。

只有真实 iFinD 汇率、Agent 与基准、美元权益曲线和人民币审计值都通过核对后，本 Loop 才算完成。
