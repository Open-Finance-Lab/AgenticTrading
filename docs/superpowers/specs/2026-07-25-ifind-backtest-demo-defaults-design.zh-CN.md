# iFinD A 股回测默认行为与诊断修复设计

## 背景

ATL 已能通过 iFinD 获取 A 股 60 分钟历史行情并完成回测，但当前回测弹窗默认使用 `2026-04-15` 至 `2026-04-23`。约 8 天的数据只能返回 16 根有效小时 K 线，少于技术指标和回测要求的 50 根。

页面还会在进入 iFinD 时默认选择 Rule-based。该规则 Agent 每次按总资产的 2% 计算买入规模，`$1,000` 只产生 `$20` 单笔预算；A 股 Demo 6 在已验证区间内不会生成可执行买单。美股 Alpaca 则默认使用 LLM，由模型在现金约束内决定仓位，因此两边使用相同初始资金时行为并不一致。

因此页面可能先把短数据错误误报为响应格式异常；即使扩展日期后成功运行，也可能显示 0 笔交易和完全不变的资金指标，但没有解释这是有效的策略结果。

## 目标

1. 为 iFinD 提供一个已验证、能产生足够 K 线的默认日期窗口。
2. A 股和美股都保留 `$1,000` 默认初始资金，并默认使用当前 Agent 的 LLM 模型。
3. 保留 Rule-based 作为可手动选择的确定性基准，不修改其 RSI/SMA 条件或 2% 仓位公式。
4. 短数据失败和 0 交易结果都向用户显示准确、可操作的英文信息。
5. 不在本次 PR 中使用固定汇率伪装美元价格；正式历史汇率转换进入下一独立 Loop。

## 交互设计

### 进入 iFinD 模式

用户从其他数据源切换到 `iFinD China A-Shares (60 min)` 时，前端先保存当前日期，然后填入以下已验证日期：

- Start date：`2026-04-01`
- End date：`2026-05-01`

初始资金保持回测弹窗的通用默认值 `$1,000`，切换数据源不得改写用户已经输入的资金。iFinD 提示文案继续说明这是 paper backtest，不涉及真实订单。日期输入框保持可编辑。

### 决策来源

两个 iFinD A 股股票池都默认保留当前 Agent 的 LLM 模型，与 Alpaca 的默认行为一致。模型选择器仍提供 `Rule-based`，用户可以主动选择不产生模型调用的确定性基准。

前端提示文案改为说明默认使用 Agent 模型、Rule-based 可选；后端两个 iFinD `MarketProfile` 的默认决策来源同步改为 `llm`，避免 UI 与直接调用后端时出现不同默认值。

### 离开 iFinD 模式

用户切换回 Alpaca 或 vn.py 模拟数据时，前端恢复进入 iFinD 前保存的日期，连同现有的股票池、标签页和模型恢复行为一起执行。初始资金在整个切换过程中保持不变。

### 错误提示

当后端错误包含 `minimum=50`、`valid bars` 或现有的少于 50 根 K 线标记时，前端统一显示：

> iFinD returned fewer than 50 valid bars. Use a wider date range (about one month) or check data permissions.

该判断必须排在通用的响应格式错误判断之前。

### 0 交易结果

回测成功但没有成交时，Trading Log 显示：

> No trades were executed. The selected strategy produced no executable orders.

Final Value、Cumulative Return、Max Drawdown 和 Sharpe Ratio 继续展示真实的零交易计算结果，不制造交易或修改指标。回测配置区保留数据源、股票池、模型/Rule-based、日期和初始资金，便于用户判断本次运行使用了什么条件。

## 不修改的内容

- 不提高规则 Agent 的 2% 仓位比例。
- 不强制最少买入 1 股，也不在本次改动中引入 A 股 100 股一手规则。
- 不改变 `$10,000` 的现有最大初始资金限制。
- 不增加真实交易、实盘下单或 iFinD 凭证前端输入。
- 不改变 Alpaca 和 vn.py 模式原本的日期或资金输入。
- 不把 iFinD 原生人民币 OHLCV 除以固定汇率，也不把人民币数值错误声明为已完成美元转换。

## 数据流

1. 用户打开回测弹窗，初始资金默认为 `$1,000`，模型来自当前 Agent。
2. 用户选择 iFinD，`syncMarketDataSourceUI()` 保存当前日期并应用 iFinD 一个月日期窗口，不改写资金。
3. iFinD 默认保留 Agent 的 LLM 模型；用户也可显式选择 Rule-based。
4. 用户运行回测，现有请求继续提交日期、资金、股票池、60m 周期和决策来源。
5. 后端使用 iFinD 原生人民币历史 K 线执行既有规则或 LLM 回测。
6. 成功但没有成交时显示明确空状态；失败时按错误类型显示行动建议。
7. 用户离开 iFinD 时，前端恢复原来的非 iFinD 日期，资金保持不变。

## 下一 Loop：历史汇率转换

历史汇率转换作为独立设计和 PR 实现：市场数据保留原生币种元数据，通过回测日期对应的 USD/CNY 历史汇率建立美元计价视图，统一交易记录、权益曲线和跨市场排名。该实现不得硬编码单一汇率，并需明确汇率数据缺失、节假日对齐和最终展示币种。A 股 100 股一手规则继续作为独立的成交模型需求评估。

## 测试标准

- 前端契约测试确认通用默认资金仍为 `1000`，iFinD 推荐日期为 `2026-04-01` 至 `2026-05-01`。
- 前端契约测试确认进入 iFinD 时保存并应用日期、保持资金，离开时恢复日期。
- 市场配置和前端契约测试确认两个 iFinD 股票池默认使用 LLM，同时继续允许 Rule-based。
- 前端契约测试确认 `minimum=50` 和 `valid bars` 会进入短数据错误分支。
- 前端契约测试确认成功但 0 成交时显示新的空状态文案。
- 现有 iFinD 股票池、LLM、请求参数、英文 UI 和凭证安全测试继续通过。
- 规则 Agent 单元测试继续通过，证明核心交易算法未被修改。

## 验收结果

使用已配置的 iFinD 服务和推荐日期运行回测时，每只 Demo 6 股票应获取约 84 根有效 60 分钟 K 线。默认运行使用当前 Agent 的真实 LLM 模型；选择 Rule-based 和 `$1,000` 时允许出现 0 笔交易，但页面必须明确说明策略没有产生可执行订单。所有指标都来自真实回测结果，不是贴图或固定展示值。
