# Configuration reference

Per-variable reference for the backend's environment variables. `dashboard/backend/app.py` loads `dashboard/.env` (not the repo-root `.env`; copy the root `.env.example` there) and skips it silently when `python-dotenv` or the file is missing. Most knobs are read once at import, so restart the service after changing one; entries read per call or per request say so. That distinction matters locally and in tests only: on Render no running process sees a changed value until a deploy. Pick "Save and deploy" (redeploys the current build with the new values; no code change, merge or rebuild); "Save only" waits for the next deploy. "No code change" below means exactly that. `.env.example` (repo root) is the operator template. `CLAUDE.md` holds the rules and an index of the names that carry one; names with no `CLAUDE.md` line (`LLM_MAX_OUTPUT_TOKENS`, `AI_HEDGE_FUND_TIMEOUT_SECONDS`, `RESEARCH_RUN_ESTIMATE_USD_CENTS`, `RUN_RECOVERY_ON_STARTUP`, and the `.env.example`-only names) are documented only here; this file holds the per-variable detail. Where the template and this file disagree, trust this file and the code.

Adding a variable:
1. Document it in `.env.example` (commented out if opt-in).
2. Document it here, under the matching group.
3. Add a `CLAUDE.md` line only if a rule binds (breaking it costs money or security).
4. Strip or pin it in `dashboard/backend/tests/conftest.py` if it changes spend, mail, auth or cache behaviour, so a developer's exported shell value cannot skew the suite.

Defensive-parse rule: parse operator integers with a logged fallback, never a bare `int(os.getenv(...))` at module scope. A junk or blank Render field then costs one log line instead of killing app boot, which a bare `int()` once did. Modules still violating the rule are flagged **Trap** in their entry; the `.env.example`-only names `AGENT_AUTH_CACHE_TTL_SECONDS`, `BASELINE_QUEUE_MAX` and `MARKET_DATA_CACHE_MAX_ENTRIES` and the rows flagged "bare" in the backlog table also parse bare.

Entry fields: default and range; **Set by** (operator = Render dashboard or `dashboard/.env`; internal = set by code, never by hand); **Reader** (`file::symbol`); effect, cost or security impact; why; tests. Paths are relative to `dashboard/backend/` unless they start with `dashboard/`, `.github/`, `docs/` or `packaging/`. **Rule: CLAUDE.md** marks an entry whose binding rule lives there; the entry then carries the reader, mechanism, why and tests but not the rule sentence itself, so the two copies cannot drift. Variables documented only in `.env.example` (the `DISCORD_*`, `SESSION_*`, `OPENROUTER_REASONING_*`, `AUTH_LOGIN_*` / `AUTH_SIGNUP_*` families and others) are not repeated here.

## Credentials and market data

### `ALPACA_API_KEY` / `ALPACA_SECRET_KEY`
Alpaca paper-API credentials for historical bars and the read-only paper account views; nothing places Alpaca orders (the trading host is hard-coded to the paper endpoint). Set by: operator; secrets. Fallback `credentials/alpaca.json` (gitignored; `credentials/alpaca.json.example`; keys `api_key|apiKey`, `secret_key|secretKey`); env wins. Reader: `infrastructure/market_data/alpaca_bars.py::AlpacaDataLoader._load_credentials`; also `infrastructure/brokers/alpaca_paper.py`, `infrastructure/market_data/quotes.py`. Unlike `app.py`, every script in `dashboard/scripts/` that calls `load_dotenv` (`refresh_daily_leaderboard.py`, `refresh_live_leaderboard.py`, `refresh_leaderboard_baselines.py`, the billable `deploy_leaderboard_model.py`, `backfill_runs_to_postgres.py`, `probe_instruction_sensitivity.py`) loads both `dashboard/.env` and the repo-root `.env`, and `integrations/discord_bot.py` ends with a bare `load_dotenv()` that walks up to the root `.env` when `dashboard/.env` is absent. Keep prod keys and database URLs out of the root `.env`.

### `ALPACA_DATA_FEED`
Optional; default `sip` (`DEFAULT_ALPACA_FEED`); `iex|sip|delayed_sip|otc`, case-insensitive; empty means default. The tape behind every backtest, baseline and leaderboard curve. IEX is about 2.5% of volume, a poor benchmark for DJIA or multi-name windows. Set by: operator. Reader: `infrastructure/market_data/alpaca_bars.py::configured_feed_name`.
- A bad value raises `AlpacaFeedConfigError`, deliberately fatal: silent substitution ships the opposite of what the operator asked for. Pinned by `test_unknown_feed_raises` (`tests/infrastructure/market_data/test_alpaca_bars.py`). A SIP "subscription does not permit" refusal retries once on IEX with the unclamped `end`, and the frames are stamped so the result is never ranked as SIP unnoticed.
- Curves priced off different feeds are not comparable. `domain/leaderboard/service.py::_resolve_cached_run` (via `_find_cached_run`) reuses an `agent_runs` row on (mode, start_date, end_date, llm_model) within the board session, NOT on feed; capital and prompt only rank candidates, never filter, because a miss would trigger unbounded billable recompute. After changing the value, force-refresh rather than let old and new rows rank together.
- Force-refresh after a feed change, each with header `X-Leaderboard-Refresh-Secret` (the GET also accepts an admin session): Competition board `GET /api/v1/leaderboard?refresh=true`; Live board `POST /api/v1/leaderboard/live/refresh?force=true` (202, async, 20/h per client; replays the month from the 1st). Both recompute only auto-compute baseline rows and never bill. Not `POST /api/v1/leaderboard/daily/refresh`: it covers only the retired daily window (`resolve_leaderboard_config("daily")`), and it defaults `deploy_models=True`, which BILLS every competition LLM entry. Its script (`python dashboard/scripts/refresh_daily_leaderboard.py --remote --force`) defaults to baselines only but is daily-only too. LLM entries re-run only with `deploy_models=true` (script flag `--models`).
- `_warn_on_feed_drift` (from `ensure_leaderboard_runs`) warns once per distinct drift per process about cached baseline rows on another feed (LLM entries are not in that loop); warning-only on purpose, since treating drift as "missing" would re-fetch Alpaca on every public page load. Every run records `metadata.market_data_feed` (or `mixed`), `sip_fallback_to_iex` and `end_clamped` via `feed_provenance()`; `dashboard/scripts/diff_backtest_runs.py` refuses to compare runs that differ on them, and the bar-cache key includes the feed.

### `ALPACA_SIP_DELAY_MINUTES` / `ALPACA_ALLOW_RECENT_SIP`
Optional; defaults `15` / off. A Basic plan may query SIP history only once `end` is 15 minutes old, so a request reaching into that window has `end` clamped to now minus the delay, never earlier than `start`. Set by: operator. Reader: `infrastructure/market_data/alpaca_bars.py::sip_delay_minutes`, `allow_recent_sip`, `clamp_end_for_sip`, `AlpacaDataLoader._effective_end`.
- A delay of 0 or less disables the clamp; a non-integer warns and uses 15; IEX is never clamped. `ALPACA_ALLOW_RECENT_SIP` accepts `1/true/yes/on`; set it on a paid data plan to skip the clamp.
- Why not raise the delay: Alpaca filters bars on opening timestamp, so 15 keeps the whole 15:00-16:00 ET closing bar, but above about 65 minutes it drops it and the daily board caches that shortened curve for the session.
- Tests: `test_clamp_never_moves_end_before_start`, `test_clamp_keeps_final_rth_bar_after_close` (`tests/infrastructure/market_data/test_alpaca_bars.py`).

### `ENABLE_IFIND_ASHARE`
Optional; default off (`1/true/yes/on`). Gates `data_source=ifind_ashare`; off, validation raises `MarketDataSourceDisabled`. Needs the tokens below as well. Set by: operator. Reader: `infrastructure/market_data/provider.py::_feature_enabled` via `validate_market_data_source`. Template default `false` (`.env.example`); unlike the three `IFIND_*` credentials it is not stripped by `dashboard/backend/tests/conftest.py`, so an exported `true` leaks into the suite.

### `IFIND_REFRESH_TOKEN` / `IFIND_ACCESS_TOKEN` / `IFIND_BASE_URL`
The `ifind_ashare` source needs `ENABLE_IFIND_ASHARE=true` AND one of the two tokens. With neither, `provider.ensure_market_data_source_available` raises `MarketDataCredentialsError` and `IFindHttpClient()` raises `IFindConfigurationError`, both before any backtest work. `IFIND_BASE_URL` (default `https://quantapi.51ifind.com`) exists for controlled local tests. Set by: operator, in the Render dashboard for prod. The tokens are backend-only secrets: never in browser code, logs, run metadata or chat. Reader: `infrastructure/market_data/ifind_client.py::IFindHttpClient`.
- The refresh token wins when both are set: exchanged at `POST /api/v1/get_access_token` for a seven-day access token (iFinD's documented lifetime, not checkable in code), cached six days (`ACCESS_TOKEN_MAX_AGE_SECONDS`), re-exchanged on expiry or a 401/403 (once per call, refresh token only). A static `IFIND_ACCESS_TOKEN` is for short local runs; nothing renews it.
- The token cache is module-level (`_ACCESS_TOKEN_CACHE` plus lock, keyed by base URL and sha256 of the refresh token) because a provider, and so a client, is built in every `HourlyBacktester.__init__`. Dashboard backtests are subprocesses and still exchange once each: a known limit, do not add a cross-process store.
- Tests: `dashboard/backend/tests/conftest.py` strips all three; exported prod tokens make static-token client tests open with an unexpected exchange (about 27 unrelated failures). Design: `docs/superpowers/specs/2026-08-19-ifind-token-refresh-design.md`.

### `IFIND_ALLOW_CORPORATE_ACTION_GAPS`
Strict opt-in; default off; `1/true/yes/on`, read per call. **Rule: CLAUDE.md** (a labelled wrong number, never a silent one). Reader: `infrastructure/market_data/ifind_market_rules.py::corporate_action_gaps_allowed`. Set by: operator.
- A-share prices are unadjusted and nothing applies dividends or splits, so an overnight daily-close move above 21% (`_CORPORATE_ACTION_GAP`, wider than the 20% STAR/ChiNext band) would chart as a real loss or gain. That is usually a 除权除息 date, but it also fires on an unbanded first-week STAR/ChiNext IPO move.
- Off: `response_to_market_rules` raises `CorporateActionGapError` for the whole run, naming sampled symbol/date/move rows. Armed: the run proceeds and the dates land in `market_rule_profile.corporate_action_gaps`, shown as a results-panel row (omitted when empty).
- It does NOT correct the curve, and ex-rights moves of 21% or less (for example a 10-for-1 bonus, about 9%) go undetected. A real fix needs corporate-action cash credits, not adjusted prices (those would break the 5-yuan commission floor and 0.01 tick). Issue #346.
- Tests: `test_an_ex_rights_window_is_refused_by_default`, `test_only_a_truthy_override_permits_an_ex_rights_window` (`tests/infrastructure/market_data/test_ifind_market_rules.py`); conftest strips it.

## Bar cache

### `ATL_BAR_CACHE` / `ATL_BAR_CACHE_DIR` / `ATL_BAR_CACHE_MAX_MB` / `ATL_BAR_CACHE_TTL_DAYS`
On-disk parquet cache of Alpaca bars: `infrastructure/market_data/bar_cache.py` (`enabled`, `cache_dir`, `max_bytes`, `ttl_seconds`), resolved in `AlpacaDataLoader.fetch_bars` (`_fetch_bars_resolved`) ABOVE the `len(symbols) > 100` recursion in `_fetch_bars_uncached`, since below it chunking rather than the cache would decide what is fetched. Set by: operator.
- `ATL_BAR_CACHE`: default ON when unset. On for `1/true/yes/on`; off silently for `0/false/no/off`; off with a once-per-process-per-value WARNING for anything else (a typo'd kill switch must not stay on).
- `ATL_BAR_CACHE_DIR`: default `dashboard/storage/data/bar_cache/` (gitignored). A relative value anchors at the repo root, never cwd (the parent runs from the repo root, a backtest child from `dashboard/`; a cwd-relative path would split the cache and every run would miss). Never point it at a directory with other files: eviction touches only names matching `<SLUG>-<16hex>.parquet|json|*.tmp` (`_is_owned`).
- `ATL_BAR_CACHE_MAX_MB`: default 256, range 1-16384; a runaway bound enforced within about 60 s, not a quota. `ATL_BAR_CACHE_TTL_DAYS`: default 7, range 1-365; TTL runs off the sidecar `fetched_at`, not mtime (reads touch mtime for LRU).
- Junk or out-of-range numbers warn once and fall back to the default; they never raise (readers run per fetch, and the module is on the boot path).
- Why a file: a dashboard backtest is a `Popen` subprocess, so the in-process `market_data_store` is empty every run. It must outlive a `Popen`, not a redeploy (the live service has no persistent disk).
- Key per symbol: `(symbol, start, end, source_timeframe, configured_feed_name(), SCHEMA_VERSION)`; an entry is a parquet plus a JSON sidecar, parquet written second (commit point). The window is verbatim in the key, so only byte-identical windows hit (warmed defaults, re-runs, the index-baseline fetch); it does NOT speed up an arbitrary typed window, so do not read `fetch_seconds` as evidence it did.
- Never stored (`write_many`, whole batch; flags come from the frames' attrs, not `loader.last_fetch`): a clamped SIP window, an IEX-fallback window, a window whose `end` is under 24 h old (`window_is_settled`), an unconfigured client, an absent or empty symbol. A hit restores `loader.last_fetch` and the `.attrs` stamps (`alpaca_feed`, `alpaca_sip_fallback`, `alpaca_end_clamped`) that `feed_provenance()` persists.
- If a call holding hits gets an IEX-fallback or clamped live answer, or a wholly empty miss-fetch, `_fetch_bars_resolved` discards the merge and re-requests ALL symbols via `_fetch_bars_uncached`: no curve priced off two tapes, no partial universe into `engine.load_data`. With no hits, an empty answer returns `{}` without re-billing. Pinned by `test_a_cached_sip_hit_is_never_merged_with_an_iex_fallback` and `test_an_empty_answer_for_the_misses_cannot_publish_a_partial_universe` (`tests/infrastructure/market_data/test_alpaca_bars_cache.py`).
- Tests: `dashboard/backend/tests/conftest.py` sets `ATL_BAR_CACHE=0` (so `test_alpaca_bars.py` keeps asserting batching `[100, 100, 35]`), pops MAX_MB and TTL_DAYS and pins `ATL_BAR_CACHE_DIR` to a temp dir (popping would fall back to the tracked storage tree); cache suites opt in with monkeypatch and `tmp_path`. Default pinned by `test_cache_is_enabled_by_default` (`tests/infrastructure/market_data/test_bar_cache.py`). Design: `docs/superpowers/specs/2026-09-21-backtest-bar-cache-design.md` (the code wins on disagreement).

### `ATL_BAR_CACHE_WARM`
Strict opt-in; default off; THIS ONE SPENDS MONEY. **Rule: CLAUDE.md.** The `app.py` startup hook pre-fetches the default backtest windows into the bar cache on a daemon thread (`infrastructure/market_data/bar_cache_warm.py::warm_bar_cache`, re-run weekly by `warm_bar_cache_each_week`). Reader: `bar_cache.warm_enabled`. Set by: operator, in the Render dashboard only.
- Needs `ATL_BAR_CACHE` on too: `warm_bar_cache` returns 0 unless `bar_cache.enabled()` and `warm_enabled()`. Cost: 3 batched Alpaca calls per boot (Mag7 onboarding window plus two Dow windows, `warm_windows`), then 2 more each time the modal's default week rolls (hourly poll; Saturday 20:00 ET, 19:00 in winter, once the week's provider end is 24 h old). Dates come from `provider.default_backtest_window`, not `defaults.json`.
- Failures are swallowed; a cold cache is not an outage. The boot thread runs `enforce_size_cap()` once whenever `ATL_BAR_CACHE` is on, armed or not.
- Tests: `dashboard/backend/tests/conftest.py` and `dashboard/scripts/loadtest/stress_serve.py` force it `0`; keep both (`test_the_suite_never_warms`, `test_the_load_test_harness_never_warms_and_never_writes_into_the_repo` in `tests/infrastructure/market_data/test_bar_cache_warm.py`).

## LLM execution and timeouts

### `ANTHROPIC_API_KEY` / `COMMONSTACK_API_KEY` / `OPENROUTER_API_KEY`
Operator-owned LLM keys; secrets; set by: operator. **Rule: CLAUDE.md** (every LLM call outside the billed layer bills these keys with no reservation). `make_llm_client()` with no integration prefers `COMMONSTACK_API_KEY` (one gateway key for several vendors) over `ANTHROPIC_API_KEY`; OpenRouter is opt-in, never auto-selected. So the Trading Algo backtest hits CommonStack when its key is set, although `execute_algo` checks only `ANTHROPIC_API_KEY`. `OPENROUTER_API_KEY` also backs the AI Hedge Fund bridge (`api/routers/backtests.py` answers 503 when unset) and gates a one-time migration enabling the legacy OpenRouter platform lane (`domain/model_providers/repository.py`). Readers: `infrastructure/llm/providers/` (`__init__.py`, `commonstack.py`, `anthropic_native.py`, `openrouter.py`), `domain/chat/service.py`, `domain/backtesting/algo_service.py`. For `OPENAI_API_KEY` and `DEEPSEEK_API_KEY` see the unread section.

### `LLM_PROVIDER_READ_TIMEOUT_SECONDS`
Optional; default 180; range 30-600 (rejects a dropped or doubled digit; junk warns and falls back, never raises). Read deadline of ONE physical provider attempt, which is the whole-generation deadline because providers do not stream; connect 8 s, write and pool 60 s. **Rule: CLAUDE.md.** Reader: `infrastructure/llm/http_policy.py` (`_parse_provider_read_timeout`, `PROVIDER_READ_TIMEOUT_SECONDS`, `provider_http_timeout()`); patch that global in tests, not a re-export. Set by: operator.
- Why: timed-out attempts are never replayed at the same provider (each replay would be billed again), so lowering it trades slow-but-healthy calls for faster failover.
- Retry ownership beyond the `CLAUDE.md` rule: async callers outside the billed layer use `http_policy.acall_with_retries`. `LLMExecutionService` is the sole retry owner for billed runs: at most two same-provider repeats, only for `PROVIDER_TIMEOUT` / `PROVIDER_UNAVAILABLE` failures tagged PRE_SEND, or REJECTED within 15 s (`FAST_FAILURE_SECONDS`), after a 4 s then 12 s backoff (a Retry-After above 60 s stops it); never after a read timeout; failover is its only second chance. Chat never fails over to another model after a timeout.
- Tests: `tests/infrastructure/llm/test_chat_algo_client_policy.py` (AST scan of every non-test module under `dashboard/`), `tests/infrastructure/llm/test_provider_retry_timeout_policy.py`; conftest strips it (the tests assert the exact 180 s `Timeout` on the wire). Design and log diagnosis: `docs/superpowers/specs/2026-09-28-llm-provider-retry-timeout-design.md`.

### `LLM_MAX_OUTPUT_TOKENS`
Optional; default 2000; any positive integer (junk or non-positive warns and uses 2000, never raising at import). Per-request output ceiling of the backtest harness; lower it to cap spend in demos, raise it when OpenRouter reasoning is on. Reader: `infrastructure/llm/backtest_harness.py::_parse_max_output_tokens` (exposed as `DEFAULT_MAX_OUTPUT_TOKENS`). Set by: operator. The rescue ceiling derives from it (see below). Not stripped by conftest.

### `LLM_ESCALATE_CEILING_ON_RETRY`
Optional; default off; `1/true/yes/on`. How the single-prompt loop (`domain/backtesting/portfolio_manager.py`) answers an empty model reply, which usually means reasoning exhausted the output ceiling before any text. Reader: `infrastructure/llm/pipeline_runner.py::escalate_ceiling_on_retry`. Set by: operator.
- Off: four requests at the failing ceiling (the first plus three re-asks, logged `retry 1/4` to `4/4`), then a fifth rescue call at `RECOVERY_MAX_OUTPUT_TOKENS`. On: the first request, then straight to the rescue call (`no_text_retries=1`), matching the pipeline path and cheaper than four same-ceiling failures. An execution-layer empty reply goes straight to the rescue regardless of the flag.
- Inert when `LLM_MAX_OUTPUT_TOKENS` is already 4096 or more: the recovery ceiling then equals the default, so there is nothing higher to escalate to (`test_the_flag_is_inert_when_the_ceiling_cannot_actually_rise`, `tests/domain/backtesting/test_escalate_ceiling.py`). Conftest strips it.

### `PIPELINE_SECONDS_PER_LLM_CALL`
Optional; default 15; range 1-300; junk, zero, negative or out-of-range logs and falls back, never raising at import (a bare `int()` at module scope in `api/routers/backtests.py` once killed boot). Reader: `api/routers/backtests.py::_pipeline_seconds_per_llm_call`. Set by: operator. The assumed wall-clock of one model call, used only by `_enforce_pipeline_llm_window` to 422 a `runtime_type="pipeline"` + `decision_source="llm"` window that the fixed `PIPELINE_SUBPROCESS_TIMEOUT_SECONDS` (3600) cannot finish. 422, not 503, because the caller can shorten the window.
- Estimate (`_estimated_pipeline_llm_calls`) = trading days x bars per day x max(1, decision steps) + trading days x post-trade steps (run once a day), against `_max_pipeline_llm_calls()` = (3600 - `SUBPROCESS_TIMEOUT_OVERHEAD_SECONDS` 600) // this value = 200 at the default. Trading days is a weekday count. Bars per day is per market (`_pipeline_decision_bars_per_trading_day`): 7 for US and unrecognised sources (`PIPELINE_DECISION_BARS_PER_TRADING_DAY`), 4 for iFinD A-share (`ASHARE_SESSIONS_PER_TRADING_DAY`). Do not collapse them: 7 for CN refused the shipped A-share prefill at three steps (231 against 200; true cost 132).
- A calibrated estimate, not an inverted ceiling. Nothing enforces a per-bar ceiling on the pipeline path (the only bound is per provider attempt plus one per failover candidate), so a worst-case refusal would allow about 4 bars. The safe direction is opposite to `_backtest_subprocess_timeout`, which over-provisions on purpose: this computes a refusal, so over-estimating refuses runs that would have worked (on the onboarding task, where a new user gets one pass) while under-estimating just lets a marginal run reach the 3600 s backstop. Do not tighten toward the worst case; a near-miss means the 3600 s budget is undersized for that pipeline shape.
- Headroom: the modal's default period is the latest settled US trading week (`provider.default_backtest_window`, served by `/config/defaults`; the `app.html` date inputs ship empty), at most 35 bars, so four decision steps spend 140 of 200. A 7-weekday window (49 bars) spends 196 of 200 (`test_pipeline_window_guard_allows_the_shipped_default_window`); `MAX_BACKTEST_DAYS` (14 calendar days) hits the bound sooner.
- Tests (`tests/test_backtests_router.py`): `test_pipeline_seconds_per_call_default_and_derived_call_budget`, `test_a_share_runs_are_billed_at_the_a_share_session_length`, `test_unrecognised_markets_keep_the_wider_us_cadence`, `test_the_shipped_a_share_prefill_is_not_refused_at_three_pipeline_steps`; conftest strips it. Plan: `docs/superpowers/plans/2026-09-14-pipeline-llm-window-preflight.md`.

## Billing and Credits

The live LLM backtest billing path has no env var of its own: `POST /backtest/run` with `decision_source='llm'` is sign-in-only and takes `billing_mode` = `byok` or `platform_credits`. Rules in `CLAUDE.md` ("LLM backtest billing"); internals in `docs/architecture/backend-internals.md` ("LLM billing internals"). Only two paths spend Credits (the billed layer and research runs).

### `ATL_PLATFORM_PROVIDER_ORDER`
Optional; default `commonstack,openrouter`. Order in which ATL Credits (`billing_mode=platform_credits`) try platform providers. Read per call by `domain/model_providers/service.py::platform_provider_order` (used by `resolve_platform_execution_candidates` and `list_execution_options`). Set by: operator, from the Render dashboard (Save and deploy; no code change). Not in `.env.example` or `render.yaml`.
- Why CommonStack first: spend its prepaid balance before OpenRouter's. The order was hard-coded OpenRouter-first until 2026-09, and CommonStack carried traffic only because OpenRouter's key was quota-dead; topping that key up would have stranded CommonStack's balance (#522, #523).
- Omitting a provider removes it from routing: the no-code-change way to pull a drained lane. An explicit `provider_id` in the request body is honoured first only when it is in the order (else an API caller naming the pulled lane reopens it). An admin-added platform lane is reachable only once listed. Nothing routable gives 422 "ATL Credits model execution is unavailable right now."
- An invalid token rejects the whole value, prints one `WARNING` (deduplicated per raw value) and falls back to the default; a typo'd order must not half-apply. Both callers pass the registry's ids, so a well-formed typo like `commonstak` is rejected too; a new caller must do the same.
- `list_execution_options`: only platform-only lanes (not `byok_enabled`, i.e. CommonStack) move, to the end, in order. BYOK-capable providers (OpenRouter included) keep repository order because `dashboard/frontend/app.js` takes `providers[0]` of the BYOK list as its default. List order is cosmetic; routing is decided by the route.
- BYOK ignores it. Read only in the route process: the handoff carries the ordered tuple whole and `_execute_with_platform_failover` treats it as authoritative. The worker once widened a lone `("openrouter",)` to OpenRouter then CommonStack and re-added pulled lanes; do not reintroduce worker-side routing.
- Tests: conftest strips it; `test_platform_provider_order_parses_and_rejects_junk_whole`, `test_misspelled_provider_in_order_rejects_the_whole_value` (`tests/domain/model_providers/test_execution_catalog.py`); `test_worker_never_widens_the_route_s_lone_candidate` (`tests/infrastructure/llm/test_platform_credits_env_fallback.py`). Design: `docs/superpowers/specs/2026-09-23-llm-backtest-step-latency-design.md` section 5.

### `ATL_STRIPE_TEST_BILLING_ENABLED` / `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` / `PUBLIC_APP_URL`
Stripe **Test Mode** Credits purchases only. **Rule: CLAUDE.md.** Strict opt-in, default off. Set by: operator (Render dashboard). Reader: `domain/credits/config.py::load_billing_config`; routes in `api/routers/credits.py`; webhook `POST /api/webhooks/stripe`.
- Flag: `1/true/yes/on` enables, `''/0/false/no/off` disables, anything else raises `BillingConfigurationError`. Also raised at load for any key not starting `sk_test_` (no Live Mode), a webhook secret not starting `whsec_`, or a `PUBLIC_APP_URL` that is not an http(s) base URL free of credentials, query and fragment. `PUBLIC_APP_URL` is one of three required values (missing makes `BillingConfig.ready` false) and builds Checkout return URLs `{PUBLIC_APP_URL}/app?...`; `api/auth.py`, `integrations/discord_bot.py` and `api/routers/research.py` also read it.
- Not ready: only gateway-touching routes (`/credits/checkout-sessions`, admin refunds, the webhook) answer 503 via `BillingUnavailableError`; `/credits/balance` and `/credits/ledger` keep answering with `billing_available=false`. ## Persistence

### `DATABASE_PATH`
SQLite file; default `dashboard/storage/data/backtest.db` (`database.py::DB_PATH`, via `paths.py`). **Rule: CLAUDE.md.** Set by: operator. `render.yaml` declares a `/data` disk and sets `DATABASE_PATH=/data/backtest.db`, but that block is documentation: the live service leaves it unset and has no disk, so the file resets to the committed seed on every deploy ("Prod deploy reality" in `CLAUDE.md`). `protocol_runs` / `protocol_steps` (`domain/runs/repository.py`) and `idempotency_keys` live only here (no Postgres option; `idempotency_keys` stays local even under the Postgres run-history twin, for the hot per-step path). ### `USERS_DATABASE_URL` / `CONTENT_DATABASE_URL` / `AGENT_RUNS_DATABASE_URL`
Optional Postgres selectors; use pooled (`-pooler`) URLs because each store call opens a connection. Unset silently selects ephemeral SQLite for that group. **Rule: CLAUDE.md** for each. Set by: operator, in the Render dashboard.
- `USERS_DATABASE_URL` (`users.py::_build_user_store`): accounts and sessions AND the Credits store (Stripe purchase records), the model-provider store (stored BYOK keys) and the analytics store. The Robinhood connection store prefers it over `CONTENT_DATABASE_URL` (`domain/brokers/repository.py`).
- `CONTENT_DATABASE_URL`: `external_agents`, agent versions, strategies, `user_portfolios`, hosted-runtime agent credentials (`domain/agents/credential_store.py`) and research-agent runs (`domain/agents/research_store.py`); the Robinhood store uses it only when the users URL is unset. Unset: every agent wiped and every issued agent API key invalidated on deploy.
- `AGENT_RUNS_DATABASE_URL` (`database.py::_build_backtest_db` returning `PostgresBacktestDatabase`): `agent_runs`, `equity_timeseries`, `trades`, `backtest_decisions`, `run_manifest`, `run_live_progress`, plus the agent trace store (`domain/traces/repository.py`). Use a database separate from the other two.

Shared rules:
- None is called `DATABASE_URL`, the Heroku-convention name that managed-Postgres add-ons inject and unrelated projects export; an ambient value would silently bind the app to the wrong database. Nothing protects a local `uvicorn` from a value you set deliberately.
- No fallback chain between them; each factory picks its backend at import (`users.py`, `database.py`), do not collapse them. Pinned per store by `test_build_*_ignores_*` tests, e.g. `test_build_user_store_ignores_content_database_url` (`tests/test_users_postgres.py`), `test_build_agent_store_ignores_users_database_url` (`tests/test_agent_store_postgres.py`), `test_build_backtest_db_ignores_content_and_users_database_url` (`tests/test_backtest_db_postgres.py`), `test_build_trace_store_ignores_the_content_database` (`tests/test_trace_store_postgres.py`).
- Boot visibility: factories `print()` (not a logger: `dashboard.backend.*` loggers sit at WARNING in prod) `<store> backend: postgres (<host>/<db>)` or `<store> backend: sqlite (ephemeral on Render)`, so a typo'd or staging URL shows. `db_url.py::describe_database_url` never emits credentials (`?/?` when unparseable). Exceptions: the model-provider and research stores log nothing; the broker store's sqlite line prints the DB path. Labels: `run history backend:`, `trace_store backend:`, `credits_store backend:`, `analytics_store backend:`.
- Set the variable in the Render dashboard BEFORE merging code that depends on it, because the merge's deploy boots the new code against whatever is set then. Any save option is safe beforehand: the running code ignores a variable it does not read. `render.yaml` is documentation, not the deploy mechanism. Then confirm the boot line.
- A set-but-unreachable run-history URL raises instead of falling back (`test_unreachable_postgres_raises_instead_of_falling_back`, `tests/test_backtest_db_postgres.py`).
- A fully durable deployment sets all three. USERS and CONTENT point at the same Neon database so user-to-agent ownership stays joinable; AGENT_RUNS points at a dedicated project so the fastest-growing tables cannot exhaust the auth-critical database. No code path joins run tables with users or content tables.
- Postgres twins live in `*_postgres.py` siblings (the research store's is inline). Twin parity: `docs/architecture/backend-internals.md`. Conftest strips all three so the suite always runs on SQLite (`tests/test_env_isolation.py`).

## Capacity and runtime caps

### `DEFAULT_MAX_CONCURRENT_BACKTESTS`
Optional; default 5; range 0-20; junk or out-of-range prints a line and falls back to 5, never raising at import. **Rule: CLAUDE.md.** Concurrent protocol runs for an account with no `user_entitlements` row. Reader: `users.py::_default_entitlement`. Set by: operator.

### `MAX_ACTIVE_DASHBOARD_BACKTESTS`
Optional; default 5; 0 disables all dashboard backtests; unset or blank gives 5 silently; non-integer or negative prints a line and gives 5; never raising at import. Server-wide ceiling on concurrent `POST /backtest/run` children, the outer bound on the per-owner slot ledger. Reader: `api/routers/backtests.py::_max_active_dashboard_backtests`. Set by: operator. Shown to admins as `max_active_dashboard_backtests` (`api/routers/admin_users.py`).
- Why 5: equal to `DEFAULT_MAX_CONCURRENT_BACKTESTS`, so one default account can reach its own quota and no higher. A dashboard backtest is a subprocess pinning a loaded bar window. The principal bound is LLM spend (N here multiplies operator API cost by N). RAM was the original sizing (512 MB free tier); on Render Standard (2 GB) it is not obviously binding, but one child's resident set has never been measured (882 MB peak observed; the roughly 1.1 GB headroom is instance-wide). Raising it needs a budget decision and a profiled per-child footprint.
- Counts only `POST /backtest/run` children. The Trading Algo panel (`/api/algo/execute`) is single-flight through the global `algo_status` (`execute_algo` holds `_launch_lock` across check and claim) and takes no slot, so the instance can run one more child than this says; an AI Hedge Fund slot spawns per-decision subprocesses beneath it.
- The per-owner cap is keyed on the caller's browser session (`_backtest_owner_key`), never the built-in agent's session (that would put every anonymous visitor in one bucket). A session id is a caller-chosen header, so the per-owner cap is an incentive fix, not a bound; this global number is what holds. The ledger is process-local (single Render instance); an entitlement lookup failure falls back to this cap only. Conftest strips it.

### `MAX_ACTIVE_RUNS_PER_AGENT` / `MAX_ACTIVE_RUNS_GLOBAL`
Optional; defaults 5 / 100; `MAX_ACTIVE_RUNS_GLOBAL=0` disables. Active-run caps for the protocol run ledger shared by v1 and v2, checked under one `_create_lock`; over the global cap, creates answer 429 with `Retry-After: 30`. Reader: `domain/runs/service.py`. Set by: operator. 100 is the highest load the loadtest harness has exercised; raise only after a measured smoke run. **Trap:** both are bare `int(os.getenv(...))` at module scope, so a junk or blank value kills app boot. ### `MAX_LEGACY_ACTIVE_PER_SESSION` / `MAX_LEGACY_ACTIVE_GLOBAL`
Optional; defaults 5 / 50; 0 disables each. Concurrency budgets for the legacy `/api/v1/backtest/*` surface. Reader: `domain/backtesting/external_run_service.py` (module constants). Set by: operator.
- Why: that surface authenticates nothing (`_require_session` in `api/routers/external_backtest.py` accepts any non-empty `X-Session-Id`) and writes no `protocol_runs` row, so the per-agent, per-account and global protocol caps are blind to it. - Tests: conftest strips both; `test_legacy_start_is_capped_per_session`, `test_legacy_start_is_capped_server_wide`, `test_terminal_sessions_do_not_consume_the_legacy_budget`, `test_protocol_creates_do_not_pay_the_legacy_budget` (`tests/test_external_backtest_api.py`).

### `MAX_AI_HEDGE_FUND_TRADING_DAYS`
Optional; default `min(10, ceiling)`; `0` disables the hosted AI Hedge Fund runtime. Pre-flight bound applied by `_enforce_ai_hedge_fund_window` before the credential lookup, so a refused window never touches the secret store. ### `ATL_BACKTEST_WORKER`
Internal; NEVER set by an operator. `run_backtest_background` (`api/routers/backtests.py`) sets it to `1` on the environment COPY of a dashboard backtest child and nowhere else. **Rule: CLAUDE.md.** Only the literal `1` arms it; a globally exported value would make a parent skip DDL it needs. Reader: `db_url.py` (`BACKTEST_WORKER_ENV`, `init_schema_unless_worker`).
- Effect: every Postgres store twin that owns a schema (and the inline research store) calls `db_url.init_schema_unless_worker(label, self._init_schema)` from its constructor, skipping DDL in a backtest child. A child prints `<label> backend: schema init skipped (backtest worker)`; otherwise the DDL runs and prints `<label> backend: schema init <n>s`. Both directions print on purpose: the parent's timed line is the only baseline for what the child saves, and a silent skip looks identical to a build with no guard.
- The guard skips more than DDL: three `_init_schema` bodies run data statements (credits default-grant pool and backfills, model-provider scrub/seed/backfill, users `user_group` repair). A child skips them safely only because the parent applied them at boot first; a worker with no parent ahead of it (a bare CLI run with the flag exported, a future worker-only service) would silently lack them. `tests/test_backtest_worker_schema_skip.py::_DATA_MUTATING_SCHEMA_BODIES` holds that set; read it before adding a migration to any guarded `_init_schema`.
- Twin scope (12 of the 13 `_TWINS` pairs, all guarded), import-graph reasoning and pinning tests: `docs/architecture/backend-internals.md` ("Backtest-worker DDL guard (`ATL_BACKTEST_WORKER`)", under "Persistence: twin parity and analytics tables"). A new Postgres twin must call `init_schema_unless_worker` from `__init__` and be added to `_TWINS` in `tests/test_backtest_worker_schema_skip.py`. `schema_init_seconds` on the `starting` phase: "Backtest progress phases and the two-clock contract" in the same file. Tests: `test_no_postgres_twin_runs_ddl_outside_the_guard`, `test_a_twin_that_owns_a_schema_method_routes_it_through_the_guard`, `test_the_guarded_list_accounts_for_every_twin`; conftest pops it.

### `RUN_REAPER_INTERVAL_SECONDS` / `RUN_HEARTBEAT_STALE_SECONDS` / `RUN_RECOVERY_ON_STARTUP`
Optional; defaults 60 / 300 / on. **Rule: CLAUDE.md** (everything passed to `register_reaper_sweep` runs inline on the one reaper thread, every `RUN_REAPER_INTERVAL_SECONDS`). Reader: `domain/runs/service.py` (`REAPER_INTERVAL_SECONDS`, `RUN_HEARTBEAT_STALE_SECONDS`, `RUN_RECOVERY_ON_STARTUP`). Set by: operator.
- The interval is the shared reaper tick and the heartbeat cadence. There is no per-sweep interval, so per-user work multiplies by every tick; heavy periodic work gets its own thread (see `ANALYTICS_DAILY_JOB_INTERVAL_SECONDS`).
- A non-terminal run silent for the stale window is failed as abandoned by any instance's reaper; keep it well above the interval; `0` disables stale recovery. A slow sweep can therefore kill live runs.
- Recovery is on unless the value is `0`, `false` or `no`. On, boot fails all non-terminal rows, correct only when one process owns the DB; multi-worker or rolling deploys must set `0` and rely on heartbeats.
- **Trap:** the two numeric ones are bare `float(os.getenv(...))` at module scope. Not stripped by conftest.

### `EXTERNAL_AGENT_DECISION_TIMEOUT_SECONDS`
Optional; default 60. A decision later than this auto-holds the step (outcome `timeout_hold`) instead of failing the run, for external agents driving the Protocol Run API step by step. **Rule: CLAUDE.md.** Reader: `domain/backtesting/external_run_service.py::DECISION_TIMEOUT_SECONDS`. Set by: operator. **Trap:** bare `int(os.getenv(...))` at module scope. Conftest strips it.

## Robinhood live switch

### `ROBINHOOD_EXECUTE` / `ROBINHOOD_MAX_ORDER_USD`
The real-money path is additionally switched off in code by a hard-coded constant, `ROBINHOOD_LIVE_ENABLED = False` (`domain/backtesting/constants.py`, read via `robinhood_live_enabled()`), which is NOT an env var (see the constants table). Off-state behaviour and restore checklist: `docs/architecture/backend-internals.md` ("Robinhood live switch"). **Rule: CLAUDE.md.**
- `ROBINHOOD_EXECUTE`: default off; only `1`, `true` or `yes` arm it (not `on`), read fresh every call (`execution/robinhood_live_service.py::execute_enabled`). Orders go out only when it is truthy; set it only when you intend real orders. `dashboard/scripts/run_local_safe.sh` forces it `false`.
- `ROBINHOOD_MAX_ORDER_USD`: default 25 (`DEFAULT_MAX_ORDER_USD`); per-order notional ceiling on BOTH buys and sells, read on every order rather than cached at import (on Render a change still takes a deploy). Missing, unparseable, non-finite or non-positive clamps to 25 rather than disabling the cap (`max_order_usd`).
- The OAuth variables (`ROBINHOOD_MCP_URL`, `ROBINHOOD_REDIRECT_URI`, `ROBINHOOD_OAUTH_STATE_SECRET`) and `BROKER_TOKEN_ENCRYPTION_KEY` are in `.env.example`; `ROBINHOOD_MCP_TIMEOUT_SECONDS` is in the backlog table.

## Analytics and news

### `ANALYTICS_DAILY_JOB_INTERVAL_SECONDS`
Optional; default 300; range 5-3600; junk or out-of-range logs and falls back to 300. How often the analytics daily-facts worker (`domain/analytics/daily_job.py`, `start_daily_facts_worker()` from the `app.py` startup hook, before the run reaper) wakes to ask whether yesterday's `user_daily_facts` set is due. Reader: `daily_job.py::daily_job_interval_seconds`. Set by: operator.
- Own thread (`analytics-daily-facts`), NOT a reaper sweep: a whole-population batch across three databases on the 60 s reaper thread could starve run heartbeats past `RUN_HEARTBEAT_STALE_SECONDS` and mark live runs orphaned (design D23). It waits one interval before its first tick. An idle tick costs one refused day claim on `analytics_projection_jobs` plus the retention coordinator's own-clock check, so the interval buys freshness, not cost.
- The worker is the ONLY caller of `facts_migration.run_startup_migrations` (idempotent; re-seed, rollup and transition backfill, then drop the two legacy snapshot tables, in that load-bearing order; then the `activation_users` rollup backfill, which runs even if that chain failed). It runs before the first tick and is retried before each later tick until it succeeds. Never run it synchronously in `app.py` startup (it blocked the event loop). The worker also owns `rollup_day` and the retention coordinator; the reaper carries no analytics sweep.
- Tests: `tests/domain/analytics/test_daily_job.py` (forbids a reaper sweep); conftest strips it. Design: `docs/superpowers/specs/2026-09-15-admin-layer-redesign-design.md` D23, section 6.9.

### `NEWS_FEED_FROZEN`
Optional; UNSET = frozen while FinSearch's feed timers are paused (since 2026-10-11 per the code comment in `api/routers/news.py`; the pause itself is not verifiable from this repo). Read per request by `api/routers/news.py::news_feed_frozen()` (`NEWS_FEED_FROZEN_DEFAULT = True`), so flipping it needs no code change (on Render, Save and deploy). Set by: operator, in the Render dashboard.
- Frozen: `GET /api/news/signals` never calls FinSearch and serves `dashboard/config/news_demo_snapshot.json` (the last live payload). The loader owns the markers, forcing `demo: true` and `staleness_hours: null` (the committed file must not restate them), so both Home consumers (`dashboard/frontend/home-page.js`, `dashboard/frontend/home-news-signals.js`) show "Demo news" and fixed dates, not a frozen "Updated 0.2h ago" and an ever-growing "3w ago".
- Resume: re-enable the FinSearch timers on the droplet FIRST, then set `NEWS_FEED_FROZEN=0` (documented intent; the order is not checkable from code). Vocabulary: `1/true/yes/on` frozen, `0/false/no/off` live; any other value reads as frozen and warns once per value (the unfrozen path calls an upstream that may be dead; the frozen path is labelled and local).
- A snapshot that cannot load (missing, unreadable, or lacking `status` / `feed` / `signals`) fails closed to `UNAVAILABLE_PAYLOAD`; only a successful load is cached, so the next request retries; each response is a deep copy. Unaffected either way: the `news_sentiment` adapter still backs `/api/v2` backtest steps (`?as_of=`) via `execution/backtest_backend.py::load_news_sentiment` ("Fail-closed is not fail-visible" in `CLAUDE.md`).
- Tests: `tests/test_news_router.py` (`test_freeze_flag_vocabulary`, `test_freeze_flag_unset_uses_the_code_default`, `test_freeze_flag_junk_reads_frozen_and_warns_once`, `test_frozen_feed_serves_demo_snapshot_without_calling_finsearch`); conftest strips it. Also in `.env.example`.
